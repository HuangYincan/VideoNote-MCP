## 一、这是什么

VideoNote-Mcp：把「视频 → AI Markdown 笔记」封装成 MCP server（10 个工具）+ Claude 插件 Skill。
输入一条视频链接（B 站 / YouTube / 抖音 / 快手 / 小宇宙 / 本地文件 / generic yt-dlp 1800+ 站点），
输出结构化 Markdown 笔记（可带截图、弹幕+评论、说话人分离、多格式导出）。

- 无 FastAPI 后端：`app/` 是 vendored 自上游的核心流水线（`VENDOR.md` 记录来源与同步纪律）。
- 架构细节见 `02-架构设计.md`；背景与动机见 `01-目的与背景.md`。

## 三、核心数据流（改一行之前先懂这个）

```
URL / file:// / 本地路径
  → detect_platform（内置平台含小宇宙 / generic 兜底；SSRF 校验见 app/utils/url_safety.py）
  → 下载（yt-dlp 适配器 / 本地直读）→ note_results/{task_id}/raw/
  → 字幕优先；无则转写（fast-whisper / mlx / funasr / groq / bcut / kuaishou）
  → 可选：16kHz 预处理 + 超长分块 / 说话人分离
  → LLM 总结（按 provider_id 走 GPT 工厂）或停在素材包
  → 后处理（截图、弹幕评论、导出）→ 落盘 {task_id}/ 目录 + SQLite video_tasks 索引
```

- **异步任务模型**：`generate_note` / `prepare_note_material` 立即返回 `task_id`，后台
  `ThreadPoolExecutor` 执行（并发上限 `VIDEONOTE_MAX_WORKERS`=3）。
  状态机 `PENDING → … → SUCCESS/FAILED/CANCELLED`。
- **编排**：`videonote_mcp/server.py` 的 MCP 工具 → `app/services/note.py` 的任务主流程
  → `app/services/pipeline.py` 各步骤。工具层做**入口校验**（白名单/形状/URI 规整），
  app 层做流水线；原则 H6：入口显式校验，别等深处泛化报错。
- **转写缓存**：同视频（`platform:video_id`）复用上次转写，按引擎分键，不重下/重转写。
- Agent 时序：`generate_note` → **`task` 轮询** → 读 `result.markdown`。

## 四、开发约定（必须遵守）

### 验证三件套（每次改动后跑）

```bash
uv run pytest -q            # 全量 802 测试（当前基线）
uv run ruff check --select F .   # F 类（语法/未定义）——CI 门槛
uv run ruff check --select I .   # import 排序——CI 门槛
```

### CI 契约（改工具名/工具数时必须同步）

`.github/workflows/ci.yml` 的 `MCP tools/list` 步骤有 **10 工具精确名单断言**（#135/#136 精简自 39，再 #138 16→10）：
新增/改名/删除工具 → 必须同步该名单，否则 CI 红。同步清单：

1. `ci.yml` 的 `expected` 名单
2. `skills/videonote/reference/tools.md`（用户侧工具参考）
3. `docs/02-架构设计.md` 工具表（分组表）
4. `commands/videonote-setup.md`（setup 向导用工具）
5. `docs/04-使用手册.md` 工具参考表

### 凭证红线（最高优先级）

**API key / B 站 Cookie / HF token 绝不经 MCP 工具参数或 agent 对话。**
填 key 走 `! videonote providers set`（对话外用终端）；Cookie 走 `! videonote login bilibili` / `setup`。
MCP 工具接口**拒绝** key 参数（`process_media` 的 diarize 拒 hf_token；#135 后 MCP 面已无任何写配置入口）。
改凭证相关代码前先读记忆 `videonote-mcp-gotchas`。

### commit message 习惯

中文、动宾开头、附实现范围与测试数。历史模式（沿用）：

```
feat(#N): 一句话说明（+X 测试）
fix(#N): 一句话说明
docs: 回填 #N commit hash（<hash>）
```

改用户可见行为 → 同步 `docs/04-使用手册.md` + `skills/videonote/reference/tools.md` + SKILL.md；

## 七、关键 gotchas（踩过的坑，写测试/调试前必看）

1. **DB 相对路径坑**：`app/db/engine.py` 在 **import 时**读死 `DATABASE_URL`。测试/脚本必须用
   绝对路径且先设环境变量；`test_task_index` 教训——直连路径必须读回实际 `DATABASE_URL`，不能写死。
2. **stdout 被 dup2 吞**：`server` 模块级 `open(logs/mcp_stderr.log)` 并 `dup2(2)`，把 stderr 重定向走。
   调试 MCP 服务不要依赖 stdout 打印；看日志文件。
3. **MCP 调试用官方库**：`mcp.client.stdio` 的 `stdio_client` 起真客户端（conftest / ci.yml 有样例），
   不要手写裸 JSON-RPC。
4. **uvx `--with` 顺序**：`uvx --with mlx-whisper videonote ...` —— `--with` 必须在工具名**前**。
5. **mlx-whisper 仅 macOS**：CI 是 Linux → 平台相关测试必须 `@unittest.skipUnless(sys.platform=="darwin", ...)`。
6. **`notes_dir` 语义**：是**输出**目录（笔记/导出写往哪），不是素材输入目录；传 `file://` 会规整成本地路径。
7. **stdout 输出给 MCP 的边界**：stdio 模式下任何 print 都可能污染 JSON-RPC 帧。
