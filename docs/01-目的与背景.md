# 01-目的与背景

## 为什么做这个项目

一个成熟的 AI 视频笔记工具能输入 B 站 / YouTube / 抖音 / 快手 / 本地视频链接，经过 **下载 → 转写 → LLM 总结**，输出结构化的 Markdown 笔记，还支持对笔记的 RAG 问答。

但它的能力被封装在一个 **全栈 Web 应用** 里（FastAPI 后端 + React 前端 + 可选 Tauri 桌面端）。对 AI agent 来说，想用这套能力必须：

1. 启动完整的后端服务（还要配 FFmpeg、whisper 模型、LLM Key）；
2. 通过 HTTP 接口 + 轮询去驱动异步任务；
3. 引入一套与本项目无关的 Web 依赖。

本项目要解决的就是：**把「视频 → 笔记」这一最核心的能力从 Web 应用中抽取出来，封装成独立 MCP 工具，让 agent 无需额外 Skills 即可直接调用。**

## 要解决什么问题

| 问题 | 本项目方案 |
|------|-----------|
| 后端大量 HTTP 端点对 agent 不友好，需手动拼请求 + 轮询 | 抽象为语义化 MCP 工具 |
| 必须跑起 FastAPI + Web UI 才能用 | 内嵌流水线，agent 直接驱动 |
| RAG 问答依赖 ChromaDB + embedding 模型，体积大 | **砍掉 RAG**：agent 拿到 Markdown 后自己读、自己答 |
| LLM Key 配置藏在 Web 界面里 | 默认由当前 Agent 写笔记，无需 LLM key；后备 LLM 用终端 `videonote providers set` 配置，MCP `get_config` 只读检查 |
| 转写要么本地 whisper（要下模型），要么云端（要 key） | 两者都保留，通过终端 `videonote setup` / `videonote transcriber set` 切换 |

## 为什么采用"内嵌流水线"而非"HTTP 包装"

最初考虑过做一个**薄 HTTP 包装层**（MCP 转发到正在运行的上游后端）。但经评估放弃，原因：

1. **依赖后端在跑** —— agent 调用前得有人先把整个后端启动起来，等于没解决问题；
2. **核心流水线与 FastAPI 解耦良好**（已核实 `gpt/`、`transcriber/`、`downloaders/`、`db/` 零 FastAPI 依赖），可复制核心后独立运行；本仓库已有多处分叉，不能整树覆盖上游更新；
3. **自包含分发** —— 独立仓库 `pip install` 即用，方便作为 MCP 注册。

## 与上游的关系

- 本仓库 `app/` 目录是从上游流水线项目 **复制（vendored）** 而来的，不依赖其 pip 包。
- 复用方式与边界、同步流程见 [VENDOR.md](../VENDOR.md)。
- 不做 RAG 问答、不内置 PDF/DOCX 编译服务。确定性字幕导出由 MCP 完成；LaTeX/Typst 独立模板供 Agent 基于底稿排版，PDF 需本机编译成功，详见 [03-预期效果](03-预期效果.md)。

## 目标用户

- 使用 Claude Code / 其他 MCP 客户端的开发者，希望 **"给我这个视频链接的笔记"** 一句话搞定。
- 希望把「视频 → 笔记」流水线能力接入自己 agent 工作流的用户。
