# 03-预期效果

## 能力清单

使用前后对比：

| | 之前 | 之后 |
|---|------|------|
| 生成视频笔记 | 启动后端 → Web UI → 粘贴链接 → 等任务 → 复制 Markdown | agent 一句「生成这个视频的笔记」即可完成 |
| 对笔记提问 | 需要后端 RAG 接口 + ChromaDB | agent 直接读 Markdown 回答 |
| LLM 配置 | Web 设置页填写 | `add_provider` 工具 / 复用旧 DB |
| 转写引擎 | 设置页切换 | `set_transcriber` 工具 |
| 平台支持 | 同上（YouTube/B 站/抖音/快手/本地/小宇宙） | 不变，全部保留（小宇宙经 yt-dlp generic 提取器覆盖） |
| 前端/Web 依赖 | FastAPI + React 全栈 | **零**，纯 Python MCP |

## 交付物

1. **独立仓库 `VideoNote-Mcp`**（可推送到 GitHub），包含：
   - `videonote_mcp/` —— FastMCP server，37 个工具；
   - `app/` —— 内嵌的 vendored 核心流水线；
   - `skills/videonote/SKILL.md` + `.claude-plugin/marketplace.json` —— agent 使用 Skill，随 marketplace 一键安装；
   - `docs/` —— 中文文档；
   - `pyproject.toml` + `install.sh` —— 一键安装。
2. **安装体验**：`uv sync` 装依赖 → `claude mcp add` / `.mcp.json` 注册 → skill 链接，即可在 Claude Code 中使用。

## 验收标准

- [ ] `uv sync` 能干净安装，`videonote` 启动后 `health_check` 返回 ffmpeg/db/whisper 状态。
- [ ] MCP 注册后 `/mcp` 能看到 `videonote` 及 37 个工具（CI 有断言，漂移会红）。
- [ ] 端到端：对本地音频/视频文件或一个短视频链接，`generate_note` → `get_task_status` 轮询返回 Markdown，且 agent 能仅凭该 Markdown 回答用户问题。
- [ ] 配置闭环：CLI `! videonote providers set` 填 key → `list_models` → 用该供应商生成笔记成功（MCP `add_provider` 不再收 api_key）。
- [ ] 转写切换：`set_transcriber("groq")` 后任务走云端转写。
- [ ] 负例：FFmpeg 缺失时 `health_check` 明确报告；不支持链接 `validate_url` / `generate_note` 给出清晰错误。
- [ ] `docs/` 文档齐全且与实现一致，每个关键节点在 `CHANGELOG.md` 有记录。

## 暂不做的（v2 候选）

- **RAG 问答 / ChromaDB** —— agent 自己读 Markdown，若后续需要可用可再引入。
- **PDF/DOCX 导出** —— 可后续加一个 `export_note` 工具调用 vendored `utils/export.py`。
- **与上游自动同步** —— 目前手动同步（`VENDOR.md` 有步骤），后续可加 CI 检查差异。
