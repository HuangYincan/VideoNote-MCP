## P0 — 正确性 / 安全（先修）

### 1. 步骤任务永不 SUCCESS（三个工具实质不可用）

`_run_step_task`（`videonote_mcp/server.py:256-269`）写完 `result.json` 后**不** `_write_status(SUCCESS)`。`get_task_status` 只在 `status == "SUCCESS"` 时读结果（`:628`）。

因此 `transcribe_media` / `extract_frames` / `summarize_note` 会一直停在 `INITIALIZING`/`PENDING`，Agent 按文档轮询永远等不到。完整 `generate_note` 没事，因为 `NoteGenerator` 自己写 SUCCESS。

### 2. 截图目录读错环境变量

`app/services/note.py:57`：

```python
IMAGE_OUTPUT_DIR = os.getenv("OUT_DIR", "./static/screenshots")
```

`config.py` 设的是 `IMAGE_OUTPUT_DIR`。非便携截图落到 CWD，`_absolutize_images` / cleanup 按数据目录找 —— 图丢、目录泄漏。

### 3. `generate_note` / `prepare_note_material` 不认 `file://`

`_coerce_local_path`（含 `unquote`）只用于 `transcribe_media` / `extract_frames`。主入口用 `Path(video_url).expanduser().exists()`（`server.py:445, 555`）。`file:///Users/.../foo%20bar.mp4` 会误报「本地文件不存在」。Windows `file:///C:/x` 解析出 `/C:/x` 也会假阴性。

### 4. 未知 `task_id` 被报成 PENDING

`get_task_status` 在 `status.json` 不存在时返回 `{status: PENDING}`（`server.py:615-618`）。拼错 / 已 cleanup 的 id 会被 SKILL 一直轮询。应返回 `NOT_FOUND`。

### 5. 凭证仍可经 MCP 进对话

安全红线写「key 只走 `! videonote providers set`」，但：

- `add_provider(api_key=...)` **必填** key
- `update_provider` 仍收 `api_key`
- `set_downloader_cookie` 收完整 cookie
- `diarize_media(hf_token=...)` 收 HF token

Cookie / SESSDATA / HF token 进 tool call = 进对话上游。应收紧：MCP 拒绝敏感字段，或明确返回「请用 CLI」；`add_provider` 允许先建空 key。

### 6. 已保存的 `hf_token` 不被 `diarize_media` 读取

setup 把 token 写进 `app_config.json`（`cli.py:464`），`diarize_media` 只看参数和 `HUGGINGFACE_HUB_TOKEN`（`diarization.py:52`）。用户按向导配完，工具仍要再要一次 token。

### 7. `wait_for_note` 阻塞 stdio 事件循环

工具体内 `time.sleep` 轮询（默认 120s）。SKILL 已禁止，工具还在。Agent 一旦调用会卡住同进程其它工具。删掉、立刻返回、或真正异步 + MCP progress。

### 8. 独立步骤任务不进 `video_tasks`

`transcribe_media` / `extract_frames` / `summarize_note` 只写 `status.json`，不 `insert_video_task`。`_write_status` 的 `update_task_status` 对不存在行直接 skip。`list_tasks` 看不到这些任务。

### 9. 并发门禁 TOCTOU

检查 `_task_futures` 再 `submit` 不是原子的（`server.py:485-515` vs `_guard_concurrency`）。两个并行 `generate_note` 都能过门禁，超过 `VIDEONOTE_MAX_WORKERS`。`generate_note` / `prepare_note_material` 还复制了一份门禁，没走 `_guard_concurrency()`。

### 10. Cookie 临时文件泄漏

Bilibili / generic 把 Netscape cookie 写到 `/tmp`（`NamedTemporaryFile(delete=False)` / `mkstemp`），默认 umask、从不 unlink。抖音 `__init__` `print(self.headers_config)` 含 Cookie，会进 `mcp_stderr.log`。secret 文件（`downloader.json`、`app_config.json`、SQLite）无 `chmod 0600`。

### 11. `xiaoyuzhoufm_download.py` 导入即 HTTP

硬编码 Next.js `_next/data` URL，模块 import 就 GET + `print`。不在 `SUPPORT_PLATFORM_MAP` 里，但任何误 import 都会打网。应删或惰性化。

### 12. 预处理清理文件名算错

`cleanup_preprocess_files(wav)` 用 `foo_16k.wav` 的 stem 再拼 `_16k`，找不到真正的 `foo_16k.wav` / `foo_part_*.wav`（`audio_preprocess.py:136-152`）。本地路径还会把中间 wav 写到用户源文件旁边。

### 13. CI 不跑测试

`.github/workflows/ci.yml` 只 `import` + `tools/list` + `providers list`。`pyproject.toml` 无 pytest/ruff extra。回归全靠人手。应 `uv run pytest`，并加 ruff。

### 14. 文档代差（会误导后续改动）

`docs/02-架构设计.md` 仍写：14 个工具、扁平 `note_results/{task_id}.json`、无 pipeline/generic/FunASR。`docs/00` 写「11 个工具」。`VENDOR.md` 缺 `generic_downloader` / `funasr` / `pipeline` / `merge` / `diarization` / `export`，章节编号重复「5.」。Skill `tools.md:16`「一次一个任务」vs 代码 `MAX_WORKERS=3`。README / docs/04 同样有串行残留。

### 15. `__version__` 漂移

`videonote_mcp/__init__.py` = `0.1.0`，`pyproject.toml` = `0.1.4`。08-16 的插件 userConfig / setup 已上 `main`，版本未 bump。

## P1 — 工具面 / Agent DX

### 16. 37 个工具已过载，返回值全是 JSON 字符串

FastMCP 本可返回 dict/Pydantic。现在 `json.dumps` 再被协议包一层，Agent 要 `loads` 两次。重叠路径：

| 用户意图 | 可走路径 |
|---|---|
| 一条视频出笔记 | `generate_note` **或** `prepare_note_material` + Agent **或** 四步拆开 |
| 查进度 | `get_task_status` / `wait_for_note` / `list_tasks` |
| 转写 | 任务结果 / `get_task_transcript` / `export_transcript` |

建议：**保留端到端 + 素材包 + 状态/清理**；步骤工具降为高级/内部，或拆 MCP Resource（`videonote://task/{id}/transcript`）。`generate_note` 16 个参数应变体（`mode=note|material`）+ 配置默认。

### 17. `generate_note` 强制 `provider_id`

即使 setup 已有默认供应商/模型，不传就抛（`server.py:438`）。docstring 却写「省略时取默认」。应取唯一已填 key 的供应商 + `default_model:{id}`。

### 18. `agent_direct` 写了没人读

setup 持久化 `app_config.agent_direct`（`cli.py:680-685`）。没有任何 MCP 工具读它。Skill/docs/04 当成 `generate_note` 的默认。要么 server 读，要么删掉这个键，Skill 只当编排选择。

### 19. `list_models` 返回形状不一致

实时 API → `{source, models: [str, ...]}`；DB 回退 → `{source, models: [{model_name, ...}, ...]}`。统一为 `{id, name}[]`。

### 20. 文档里的 `fetch_comments_danmaku` 不是工具

`pipeline.fetch_comments_danmaku` 存在；`summarize_note` docstring（`server.py:1021`）和 Skill `tools.md:76` 当 MCP 工具写。Agent 会调一个不存在的名字。暴露它，或改文档为 `fetch_comments` + `fetch_danmaku`。

### 21. 无 MCP progress

后台任务只写 `status.json`。Agent 只能盲轮询。应在 PARSING→DOWNLOADING→TRANSCRIBING→SUMMARIZING 用 `ctx.report_progress`。

### 22. 配置工具不对称

DAO 已有 `delete_provider` / `delete_model`，MCP 未暴露。没有 `get_app_config`。没有 `test_provider`（CLI 有 `providers test`）。`set_transcriber` / `plugin.json` userConfig 漏 `funasr`，也漏 `video_interval` / `comments_limit` / `default_export_formats` / preprocess。插件 MCP 启动命令没 `--with mlx-whisper`。

**已落地（2026-08-17，Phase 2d）**：MCP 新增 `delete_provider` / `delete_model(provider_id, model_name)` / `test_provider(provider_id)`（用已存 key 探测，不接受 key 参数）/ `read_app_config()`（返回 setup 默认值，过滤 hf_token 等敏感项）。Wave B 已把 `set_transcriber` docstring 与 tools.md 对齐 funasr。

### 23. SKILL 摩擦过大 + handoff 过时

强制先问全自动/手动，再列 6 项，再强制后续优化。和「给个链接出笔记」冲突。规则 6：未知 URL 现在是 `generic`，只有显式 `platform=unsupported` 或 generic **下载失败** 才该 handoff；server 失败时也常不返回 `handoff:true`。

### 24. 插件更新路径脆弱

MCP（uvx）跟 git HEAD；Skill 必须 disable+install。`plugin.json` 故意无 version。用户经常「MCP 新、Skill 旧」。`health_check` 应返回 `server_version` + 刷新命令。考虑 pin `@vX.Y.Z`。

### 25. `export_transcript` 丢错误、默认不一致

exporter 跳过失败格式，工具仍返回 `errors: {}`（`server.py:1405-1408` vs `exporter.py:69-83`）。手动导出未配格式时发明 `["srt","vtt","json"]`；自动导出空配置 = 跳过。`out_dir` / `merge_audio` 可写数据目录外（merge 默认 `cwd`）。

### 26. `get_task_transcript` 默认灌全文

空 `segment_range` = 全量。长视频一次撑爆 context。默认应截前 N 段，显式 `"all"` 才全文。`get_task_status` 先整份读 `result.json` 再 pop transcript，同样浪费。

### 27. 错误形状不统一

有的 `raise ValueError`，有的 `{ok:false}`，`fetch_subtitles` 成功甚至没有 `ok`。Agent 难写统一处理。

## P2 — 流水线可靠性 / 性能 / 笔记质量

### 28. 跨任务零缓存

每次 `generate_note` 新 `uuid4`。`gen/transcript.json` 只对**同一 task_id 重跑**有效。同一 BV 再生成会重下+重转写。应按 `platform+video_id`（或文件 hash）内容寻址。

**已落地（2026-08-17）**：`app/services/note_cache.py` —— 身份 `platform:video_id`（B 站 BV+p / YouTube v= / 抖音 / TikTok / 本地 sha256；b23 短链解析、快手、generic 解析不出则不命中），转写按来源分键（`subtitle` / `transcriber_type[:model_size]`，切换引擎/尺寸不误用）。命中把缓存 transcript 拷进 `gen/transcript.json`，下游 `has_transcript → skip_download` 即跳过下载与转写。`cleanup_all` 连 `note_cache/` 一起清。无 LRU；kuaishou/generic 的 URL→id 映射（别名表）仍未做。

### 29. `quality` 是死参数

`QUALITY_MAP`（32/64/128）存在，**没有下载器读 `quality`**。B 站写死 `preferredquality: '64'`。base.py `:19` 还 `#TODO 需要修改为可配置`。要么接上 yt-dlp format，要么从 API 拿掉。

### 30. 播放列表 / 分 P / 合集

所有下载器 `noplaylist: True`。字幕层已能解析 `p=`，MCP 没有「列出分 P / 批量提交」。应：`inspect_video` 返回分 P/时长/是否有字幕；`generate_note` 接受 `p` 或 `pages=[]`。

### 31. 说话人分离没接入主路径

`diarize_media` 是独立工具；`generate()` 即使配置了 `diarization` 也不会给 segment 打 speaker。会议纪要风格空转。

### 32. LLM 按 45MB JSON 切块，不是 token

`universal_gpt.py` 默认 `OPENAI_MAX_REQUEST_BYTES=45MB`。2 小时转写往往一整块。中文 3 字节/字，结构容易碎。应按窗口（8–16k token）+ overlap，合并时带章节大纲。`fix_markdown` 已 import 从未调用。

### 33. 视频理解成本失控

`VideoReader` 每 6s 一帧、最多 1000、3×3 网格，**整组 data URI 进第一次 LLM**。1 小时 ≈ 67 张网格图。应封顶、落盘、不要 base64 全集。截图模式会 **下载两次**（视频 + 音频）。

### 34. Whisper 默认 `tiny` + HF 超时 10s

中文质量差。`HF_HUB_DOWNLOAD_TIMEOUT=10` 防卡住，但首次下大模型会误杀。`health_check` 应区分「未下载」vs「下载超时」；默认至少 `base`/`small`。`get_transcriber(..., device="cuda")` 在 Mac 上先探测再回退，应 Darwin 直接 `cpu`/`mps`。

### 35. `load_dotenv()` 在 vendored 模块里乱跑

`note.py` / `engine.py` / 抖音 / 快手 / groq / `video_helper` 各自加载。CWD `.env` 会在 import 后覆盖 `setup_environment()` 的 setdefault。

### 36. 下载器脆弱点

- YouTube **不读** CookieConfigManager（年龄墙/机器人检测过不去）；音频常是 webm/m4a，路径按 `info['ext']` 猜
- Generic cookie Netscape host 写成 `example.com`，yt-dlp 不会带到真域名
- 无 yt-dlp `retries` / `fragment_retries`
- Douyin 硬编码 `strData` + ABogus，API 一漂就死
- Kuaishou 出错仍 `return video_details['data']` → TypeError；永远先下整段 mp4 再转码
- Bcut 轮询 500×1s 无退避
- `audio.json` 不检查文件是否还在
- `_get_transcript` 会把 `generate()` 已拉过的字幕再拉一次
- `insert_video_task` 吞掉 DB 异常

### 37. 提交前无预检

没有时长、磁盘、ffmpeg、模型就绪、供应商 key。长视频跑到 TRANSCRIBING 才因模型未下载 / 磁盘满失败。

**已落地（2026-08-17，Phase 2）**：新增 `preflight(url?, platform?, provider_id?)` 工具 —— ffmpeg / 磁盘剩余（≥1GB）/ 转写器就绪 / 供应商 key+模型（与 generate_note 解析逻辑一致）/ 队列；url 非空时预解析时长（失败不拦截）。`{ok, checks:[{name, ok, detail}], duration_secs}`。

### 38. `cleanup_all` 不动 DB + 无确认

磁盘空了、`list_tasks` 全是幽灵。`include_config=True` 清 keys/cookies，无确认 token。活着的 `mcp_stderr.log` 会被抽走 fd。

### 39. 笔记 prompt 质量

风格如小红书往「专业笔记」里灌 emoji/标题党。分块之间不共享大纲，标题漂移。默认不喂 speaker。`tiny` 中文讲座质量差，有 FunASR 也不按语言自动选。

### 42. Vendor 同步不可执行

本仓库已在 `app/` 上长出 pipeline / FunASR / 数据层。再按 VENDOR「diff -r + 重打 4 个补丁」必冲突。应列冻结分叉清单，或把分叉抽回 `videonote_mcp/`。

### 43. 安装 / 数据目录故事不统一

- checkout → `<repo>/data/` + `<repo>/models/`
- 安装包 → `~/.local/share/videonote-mcp`
- `docs/04:35` 说「所有安装方式共用 ~/.local/…」——对 clone/`uv run` **假**
- 用户级 `claude mcp add` 空 env 会遮蔽插件 userConfig（install.sh 已修，旧用户未清）
- Skill/插件不随 uvx 自动更新
- hatch wheel **不含** skills/templates（pip 装的人没有模板）
- `requires-python <3.14`，README badge 写 `3.11+`

### 44. 可观测性

- `dup2` 失败 `except: pass`（`server.py:50`），stderr 死锁会回来
- `health_check` 不含：包版本、队列长度、是否有已填 key 的供应商、mlx/funasr 是否已装、模型是否正在下
- `ThreadPoolExecutor` 无 shutdown hook，客户端杀进程时 ffmpeg/whisper 可能残留
- 进程级 `builtins.print` 劫持，依赖真实 stdout 的库会坏

### 45. 安全边角

- `notes_dir` / `export out_dir` / `merge_audio` 未走 cleanup 那套 `_safe_resolve`
- `abogus.py` 来自 TikTokDownloader，GPL-3 和本仓库 MIT 混用
- builtin Claude `base_url: "https://"` 是坑
- CLI `providers add --api-key` 出现在进程列表 / shell history（向导 `getpass` 更安全）
