# 04-使用手册

> 本手册面向两种读者：**人类用户**（如何安装、配置、调试）与 **agent**（如何调用这套 MCP 工具完成"生成视频笔记"）。快速上手见 [README](../README.md)，本手册是详细参考。

## 前提

- **uv**（Python 包管理器，必需）：`curl -LsSf https://astral.sh/uv/install.sh | sh` 或 `brew install uv`（没有 uv 走[安装方式四](#安装)，脚本内置 pip 兜底）
- **Python ≥ 3.11，<3.14**（推荐 3.12）
- **FFmpeg**：`brew install ffmpeg`（Linux：`apt install ffmpeg`）
- **LLM 供应商 API Key（可选）**：仅配置 LLM 后备总结时需要；直接转写/当前 Agent 写笔记不需要（见[配置](#配置装完必做)）
- **本地转写**：本地 whisper 需先 `videonote transcriber download <size>`，或改用云端 `groq` / `bcut`
- **GPU 加速（可选）**：NVIDIA/Linux 想用 CUDA → 装工具时 `--with torch`（whisper 自动检测 GPU，默认 CPU）；macOS Apple Silicon → `--with mlx-whisper` + `videonote transcriber set mlx-whisper`
- **CLI 命令简写**：正文里的 `videonote ...` 等价于：
  - 有 uv：`uvx videonote ...`（PyPI 包 `videonote`，v0.1.7 起）
  - 源码（方式四）：`<仓库路径>/.venv/bin/videonote ...`

## 安装

**只需 MCP，不需要安装 Skills。** 四种方式任选，推荐直接注册：

| 方式 | 命令 | 说明 |
|------|------|------|
| 一 · 独立 MCP（推荐） | `claude mcp add --scope user videonote -- uvx videonote@latest` | 运行 PyPI 已发布版本，无 Skills |
| 二 · 可选 MCP-only 插件 | `claude plugin marketplace add HuangYincan/VideoNote-MCP` + `claude plugin install videonote@videonote` | 仅注册 MCP 和默认环境配置，不分发 Skills / 命令 |
| 三 · uv tool install | `uv tool install videonote` + `claude mcp add --scope user videonote -- "$HOME/.local/bin/videonote"` | 固定版本、启动最快 |
| 四 · 克隆 + install.sh | `git clone https://github.com/HuangYincan/VideoNote-MCP.git && cd VideoNote-MCP && ./install.sh` | 源码运行；直接注册本地 MCP，无 uv 时用 pip |

JSON 客户端运行已发布包可用 [examples/mcp.example.json](../examples/mcp.example.json)，验证源码修复用 [examples/mcp.source.example.json](../examples/mcp.source.example.json)。两者都不含个人配置。配置后**重启或重连 MCP**，调用 `health_check(need_provider=False)` 验证；配置向导在终端运行 `videonote setup`，不再提供 `/videonote-setup`。

> 不要重复注册独立 MCP 与旧插件。已安装的旧 Skills / 插件缓存或 `~/.claude/skills/videonote` 不会因仓库删除而自动移除；改用独立 MCP 后，请手动停用旧插件/Skill。安装脚本不会替你删除旧配置、复制 Cookie 或链接 Skills；检测到已安装插件时跳过自动注册，避免遮蔽其环境配置；同名 MCP 注册失败时只打印配置供核对。

### 源码 MCP 与 CLI 使用同一配置

1. 克隆仓库并使用 `main`（已合并版本）或 `dev`（集成版本）；分支最新不等于 PyPI 已发版。
2. 复制 [源码 JSON 示例](../examples/mcp.source.example.json)，替换仓库绝对路径（含空格也作为一个 `args` 元素，不要额外写引号字符）。其中 `uv --directory … run --frozen videonote` 不依赖 MCP 客户端的工作目录。
3. 在终端运行以下命令，`setup` 或扫码必须用同一命令前缀：

   ```bash
   uv --directory /absolute/path/to/VideoNote-MCP sync --frozen
   uv --directory /absolute/path/to/VideoNote-MCP run --frozen videonote setup
   uv --directory /absolute/path/to/VideoNote-MCP run --frozen videonote login douyin
   ```

4. 若 MCP 的 `env` 中覆盖了 `VIDEONOTE_DATA_DIR` / `VIDEONOTE_CONFIG_DIR`，终端也需设置相同值；不要把 Cookie、API key、验证码写进 JSON 示例或对话。配置路径不会自动迁移已安装版本的凭证。
5. 重启或重连 MCP，核对 `health_check(need_provider=False)` 的 `server_version` / `data_dir` 和 `get_config().cookie_configured`。相同版本号也可能来自不同源码提交，因此仍须核对启动命令。未发布修复不能靠重新启动旧版 `uvx videonote@latest` 获得。

## 配置（装完必做）

> 数据目录随安装方式而定：**安装包**（uvx / uv tool / pip / 插件方式）用 `~/.local/share/videonote-mcp/`；**源码 clone** 用 `<仓库>/data/`（`VIDEONOTE_DATA_DIR` 可覆盖，两者互不共享——源码跑的就是仓库 data/）。同一方式内配置/笔记自动延续；安装与升级都不会清配置（只有显式 `cleanup(include_config=True)` 才清）。配好即会话内生效。

### 可选插件方式（方式二；独立 MCP 用户可跳过）

`/plugin install` 时 Claude Code 会**逐项提示填默认值**（笔记风格 / 转写引擎 / 模型尺寸 / 视频理解 / 评论弹幕 / 笔记位置，均非敏感）——存 Claude Code 配置，经 MCP `env` 注入 server，作为「配置文件缺项时的兜底默认」（配置文件优先，之后跑 `setup` 向导修改仍以向导为准）。

**填法**（`/plugin configure` 页**全部为键盘输入**，无下拉/开关）：布尔项（插图/视频理解/评论）输入 `true`/`false`；目录项（笔记位置）输入**绝对路径**，留空 = 默认；字符串项（风格/引擎/尺寸）直接输入英文 key —— 风格 `detailed`/`minimal`/`academic`/`tutorial`/`xiaohongshu`/`life_journal`/`task_oriented`/`business`/`meeting_minutes`；引擎 `fast-whisper`/`groq`/`bcut`/`kuaishou`/`mlx-whisper`/`funasr`；尺寸 `tiny`/`base`/`small`/`medium`/`large-v3`/`large-v3-turbo`。Configure 页每个字段下方的说明也列出了可填值。

装完在终端运行 **`videonote setup`** 配置转写、可选 LLM 和平台登录；重连 MCP 后用 `health_check(need_provider=False)` 体检。

> **凭证红线**：LLM key / SESSDATA 一律走 `!` 前缀在**本会话终端**输入（隐藏输入、值不过 agent 对话），或独立终端跑完整命令。下面的命令在本会话用 `! videonote ...` 前缀即可直接跑。

### 交互向导 `setup`（推荐，随时可反复进入修改）

```bash
videonote setup
```

**方向键选择 + 高亮**、**左键返回上一级**、每步自动清屏；**不是一次性程序**，随时重跑即可改配置：① LLM 供应商（填/改 key、新增中转站、**检测连接 / 列模型 / 设默认模型**；默认路径 Agent 写笔记时 key 可选，后备 LLM 才需要）→ ② 转写引擎 + 模型尺寸（未下载会提示下载）→ ③ 平台 Cookie（下拉选择）/ 默认笔记位置（持久化）/ **视频理解默认**（开/关 + 帧间隔秒数，持久化）/ **评论/弹幕整合默认**（开/关 + 评论条数，持久化，需 B 站 SESSDATA）/ **笔记默认**（`default_style` 默认 detailed、`default_screenshot` 默认关、`agent_direct` 向导默认开；历史工作流开关，server 不读此键；独立 MCP 由当前 Agent 根据任务选择工具）—— 参数不传即套这些默认。

### LLM 供应商（key 走 CLI，对话外）

内置供应商（openai / deepseek / qwen / groq / ollama…）在空库时已自动预置，id 固定、base_url 正确，**只需填 key**：

```bash
# 终端（key 不进对话；本会话里用 `!` 前缀，如 `! videonote providers list`）
videonote providers list                                  # 看内置供应商，key 为空
videonote providers set deepseek --api-key 'sk-你的key'     # 填 key（掩码回显）
videonote providers test deepseek                          # 检测连接 + 列出可用模型
videonote providers test deepseek --default deepseek-chat   # 检测并设为默认模型
```

**检测连接 / 设默认**：`setup` 向导里选中某供应商会进入「管理」子菜单（✏ 编辑 key/base_url / 🔌 检测连接 → 列出模型 → 设默认 / ← 返回）。检测用 OpenAI 兼容 `GET /v1/models`（一次验证 key/base_url 并拿到模型列表）；`/v1/models` 不可用（部分中转站/自建网关）时降级为「最小对话请求」chat 探测。默认模型持久化在 `config/app_config.json`（`default_model:{provider_id}`）—— `generate_note` **未指定 `model_name` 时优先用配置的默认模型**，再退 DB 第一条。

```text
# agent 侧（只读）：配置修改一律走终端 CLI（MCP 面无写配置工具，凭证红线最干净）
get_config()                                # 只读汇总：默认值 + providers(key 掩码) + 转写器 + cookie 状态
get_config("deepseek")                      # 附加连通性探测 → {probe:{ok, models, error}}
```

**中转站 / 自建网关**（非内置）：终端新增

```bash
videonote providers add --name 我的中转站 --api-key 'sk-中转站发的key' --base-url 'https://relay.example.com/v1'
videonote providers list                                    # 记下新供应商 id
```

**没有 LLM key？** 本地装 [Ollama](https://ollama.com) 并 `ollama pull llama3`，内置 `ollama` 供应商**无需 key**，`get_config("ollama")` 探测有模型即可用；或注册 Groq/DeepSeek 免费额度后 `providers set` 填 key。

### 转写引擎

**终端直接切换（推荐，非交互）：**

```bash
videonote transcriber list                          # 查看当前引擎与就绪状态
videonote transcriber set fast-whisper --size small  # 切本地 whisper
videonote transcriber download small                  # 下载 fast-whisper 模型
videonote transcriber download small --engine mlx-whisper  # 下载 mlx-whisper（macOS）

# B 站：优先用平台字幕（含 AI 字幕）跳过语音识别；AI 字幕需登录态
videonote login bilibili     # 扫码登录，二维码渲染进终端/会话，自动保存 SESSDATA
# 小宇宙：优先用官方文稿跳过本地 ASR（47 分钟单集否则会转写很久）
videonote login xiaoyuzhou   # 扫码登录（小宇宙 App）；`--token` 改粘贴
# 小红书：原生下载器；登录墙/验证码时需要登录态
videonote login xiaohongshu  # 扫码（本机需 Chrome/Edge）；`--cookie` 改粘贴
# 抖音：原生下载器；登录墙/风控时需要登录态
videonote login douyin       # 扫码（本机需 Chrome/Edge）；`--cookie` 改粘贴
videonote transcriber set groq                        # 切云端
```

**引擎**：`fast-whisper`（本地）/ `groq` / `bcut` / `kuaishou`（云端）/ `mlx-whisper`（**仅 macOS Apple Silicon**，GPU 加速）/ `funasr`（**中文最优**：Paraformer-zh + VAD + 自动标点）。
**whisper 尺寸**：`tiny` / `base` / `small` / `medium` / `large-v3` / `large-v3-turbo`（turbo 更快、精度略低）。
**设备**：whisper 自动检测 CUDA（有 torch+CUDA 用 GPU，否则 CPU）；macOS 用 `mlx-whisper` 走 Apple Silicon GPU。CLI `download` 用 CPU 只是下载权重、不推理。
**funasr（可选重依赖）**：中文转写质量优于 faster-whisper，自带 VAD 分段 + 中文标点。需 `uvx --with funasr --with torch` 安装；模型首次转写时自动下载（无需 `download` 命令）。未装时 `! videonote transcriber set --engine funasr` 返回安装指引。

**或 agent 侧用工具：**

```text
get_config()                         # transcriber 段：当前引擎/尺寸/就绪状态
# 切引擎/下载模型走终端（配置修改一律走 CLI）：
#   ! videonote transcriber set fast-whisper --size small
#   ! videonote transcriber download small
#   ! videonote transcriber set groq（云端，先 ! videonote providers set groq --api-key 'gsk-你的key'）
```

> whisper 模型尺寸（约）：tiny 75MB / base 145MB / small 460MB / medium 1.5GB / large-v3 3GB。够用选 small 及以下，追求精度再上 medium+。
> macOS Apple Silicon 可用 MLX Whisper（`! videonote transcriber set --engine mlx-whisper --size small`），需安装时带 `--with mlx-whisper`。

### 平台 Cookie（B 站 / 小宇宙 / 小红书等）

部分平台需登录 Cookie / token 才能拿官方字幕或高清内容：

```text
# Cookie / token 不进 MCP 工具参数（会进对话上游）——一律走本会话终端：
! videonote login bilibili        # 扫码登录，自动保存 SESSDATA
! videonote login xiaoyuzhou      # 扫码登录（小宇宙 App）；`--token` 改粘贴
! videonote login xiaohongshu     # 扫码（本机 Chrome/Edge）；`--cookie` 改粘贴
! videonote login douyin          # 扫码（本机 Chrome/Edge）；`--cookie` 改粘贴
# 或 setup 向导的 Cookie / 登录步骤
# 非交互：videonote cookie set xiaoyuzhou 'x-jike-access-token=...; x-jike-refresh-token=...'
# 非交互：videonote cookie set xiaohongshu 'web_session=...; a1=...'
# 非交互：videonote cookie set douyin 'sessionid=...'
```

小宇宙官方文稿接口 `POST /v1/episode-transcript/get` 需要登录态。access token 约 2 小时过期；配了 refresh token 后过期会自动续期。未登录时该期会回退本地下载音频 + ASR（长节目会非常慢）。

小红书走原生笔记页解析（`__INITIAL_STATE__` 视频直链），图文笔记会明确报错。公开视频有时无需登录；遇到登录墙 / 验证码时先 `! videonote login xiaohongshu`（本机需已装 Chrome 或 Edge；扫码走官网登录页，终端出 ASCII 码）。无官方字幕，转写走本地/云端引擎。

### 抖音登录（扫码）

抖音走原生 aweme 接口。同一条视频的 `/video/{id}`、`/jingxuan?modal_id={id}`（以及用户页/发现页带 `modal_id`）、App 分享短链 `v.douyin.com/...` 会解析成同一个 id，转写缓存可互命中。公开视频有时无需登录；遇到登录墙 / 风控时先 `! videonote login douyin`（需桌面环境及本机 Chrome/Edge；会显示官网登录窗口，同时在终端出 ASCII 码）。用抖音 App 扫码并确认后，**若网页要求「身份验证」，仍需在这个浏览器窗口中完成短信或刷脸二次验证**；验证码只在抖音官方页面输入，不发给 Agent。CLI 会提示二次验证并单独等待最多 5 分钟，不受已扫二维码的旧有效期影响；请勿关闭窗口。未进入二次验证时，二维码有效期以终端显示的剩余秒数为准（可能约 60 秒），过期或官网自动换码需重新运行。无需二次验证的确认回调最多等 15 秒收集主站 Cookie；只有实际取得 Cookie 后才保存，再用独立 HTTP 接口做附加校验。若提示「未能确认登录态」，表示校验受限或响应无法识别，不等于浏览器登录失败；Cookie 会保留，可先尝试下载，不必仅因这条提示重复扫码。只有接口明确拒绝认证（HTTP 401）才提示登录态无效。无桌面环境或扫不了可用 `--cookie` 粘贴。

开发工作区中的修复不会自动进入 `videonote` / `uvx` 已安装版本。在仓库根目录用 `.venv/bin/python -m videonote_mcp.cli login douyin` 验证当前源码；不要把重试旧安装包当成验证本地修改。

**扫码成功，但 MCP 仍报 `Fresh cookies (not necessarily logged in) are needed`：**

- 旧版 `inspect_video` 的抖音预检误走 yt-dlp 的未签名详情接口；该错误只是未拿到详情，不足以证明 Cookie 过期。修复版预检复用原生下载器的 Cookie、msToken 和签名请求，三种链接统一输出 `/video/{id}`。详情缺失或图文作品仍会报错，不以「已登录」代替实际可访问性验证。
- 核对 **MCP 的 `health_check(need_provider=False).data_dir`** 与扫码命令的数据目录，并通过 `get_config().cookie_configured` 确认 MCP 是否配置了 `douyin`。默认源码用 `<仓库>/data/`，安装版用 `~/.local/share/videonote-mcp/`（设置 `XDG_DATA_HOME` 时随之变化），两份 Cookie 不会自动同步。还需检查是否显式设置了 `VIDEONOTE_CONFIG_DIR`。
- 验证未发布的源码修复时，MCP 启动命令也必须指向同一份源码，例如 [源码 JSON 示例](../examples/mcp.source.example.json) 中的 `uv --directory <仓库绝对路径> run --frozen videonote`，且数据/配置目录与源码登录命令一致，然后重连或重启 MCP；只在终端用源码扫码不够。不要在对话中粘贴 Cookie，也不要无提示覆盖另一份账号配置。
- msToken 初始化的网络/TLS、HTTP 或无效响应错误不等于登录过期。修复版会保留现有 Cookie 与 ABogus 签名，以空 msToken 继续尝试视频详情请求，最终以详情接口结果为准；取消任务时不会继续请求。若详情仍失败，再检查对应网络/平台验证问题，不因初始化失败直接要求重扫。预检成功仅代表拿到元信息，不代表音频下载、转写已经成功。

## 环境变量（可选）

| 变量 | 作用 | 默认 |
|------|------|------|
| `VIDEONOTE_DATA_DIR` | 数据根目录（SQLite / 笔记 / 截图 / 配置） | 安装模式 `~/.local/share/videonote-mcp`，源码 `仓库/data` |
| `VIDEONOTE_NOTES_DIR` | 默认笔记输出目录（指定 `notes_dir` 时的兜底） | `note_results/{task_id}/` |
| `VIDEONOTE_CONFIG_DIR` | 配置文件目录（转写/cookie/app 配置） | `<数据目录>/config` |
| `VIDEONOTE_MODEL_DIR` | whisper / mlx 模型目录 | `<数据目录>/models`（源码 `仓库/models`） |
| `VIDEONOTE_MAX_WORKERS` | 单个 MCP 会话内**并发笔记任务数** | 3 |
| `VIDEONOTE_STDERR_LOG_MAX_MB` | `mcp_stderr.log` 轮转阈值（超限改名 `.log.1`） | 50 |
| `VIDEONOTE_CACHE_TTL_DAYS` | 跨任务转写缓存滑动 TTL（天）；命中刷新；`0`=不过期 | 30 |
| `VIDEONOTE_CACHE_MAX_MB` | 跨任务转写缓存总量上限（MB）；超限按最久未用淘汰；`0`=不限制 | 2048 |
| `VIDEONOTE_ALLOW_EXTERNAL_PATHS` | **放行数据目录外的本地文件输入 / 输出目录**（`1`/`true` 开） | 关（默认拒绝并报错说明放行方式） |
| `VIDEONOTE_ALLOW_DESTRUCTIVE_CLEANUP` | **放行 `cleanup(include_config/include_models)`**（删 LLM key/cookie/模型，不可逆） | 关（默认拒绝，dry_run 标注「将拒绝清理」） |
| `HF_ENDPOINT` | HuggingFace 镜像（国内下载慢/卡时用） | 官方 `https://huggingface.co`；国内可 `https://hf-mirror.com` |

**会话内有限并发 + 多会话并行**：每个 Claude Code 会话独立起一个 MCP server 进程。普通 `generate_note` / `prepare_note_material` 受 `VIDEONOTE_MAX_WORKERS`（默认 3）admission 限制，提交时在锁内预占名额，覆盖排队与执行全生命周期，超限会拒绝新提交；**`batch_generate_notes` 仅用于后备 LLM 的合集**，单次最多提交 50 条，绕过普通 admission，由线程池排队。**多个会话**可各自并行（互不干扰）。**注意**：Claude Code 客户端对「同一条消息里多个并行 MCP 工具调用」处理不稳—— **不要在同一消息里并行塞多个 `generate_note` / `prepare_note_material`**。**多任务轮询请用轻量 `task(task_id)`**。需要取消用 `task(task_id, action="cancel")`。whisper / MLX 转写吃 CPU/内存；所有会话共用同一个 SQLite。

**协作式取消边界（#149/#150）**：对 `generate_note` / `prepare_note_material` 调用 `task(task_id, action="cancel")` 后，取消事件会沿平台字幕、下载、ASR、音频预处理、ffmpeg、VideoReader 抽帧、说话人分离、B 站弹幕/评论聚合和笔记后处理的检查点传播。运行中的任务返回 `CANCELLING`，由 worker 在下一阶段边界捕获 `TaskCancelledError` 后写 `CANCELLED`；排队中的任务可直接取消。取消不是线程/进程硬中断；正在进行的 HTTP/模型推理只能等自然返回。

**提交失败回滚与索引错误**：任务提交前会创建任务目录、状态文件和 `video_tasks` 索引；admission、参数准备或线程池提交失败时回滚内存注册表、任务目录、manifest 与索引。清理失败不替换原始提交错误，会以 `errors`、`manifest_error`、`index_error`、`cleanup_error` 等结构化诊断记录并附加到原始异常。DAO 的索引插入/更新/删除失败会 rollback 后重新抛出；流水线完成阶段的索引失败不会发布 `SUCCESS`。



MCP 工具面可被 Agent 以任意输入驱动，防被不可信内容诱导「转写任意本地文件回传 / 写任意位置 / 清空凭据」：

- **本地媒体输入与输出目录默认限数据目录内**：`generate_note` / `prepare_note_material` 的本地视频路径、`process_media` 的 `files` / `audio_file` / `out_dir`、`notes_dir`（含 env `VIDEONOTE_NOTES_DIR` 兜底）落在数据目录外 → **拒绝执行**，报错信息带放行方式。
- **放行**：`VIDEONOTE_ALLOW_EXTERNAL_PATHS=1`（或插件设置 `allow_external_paths`=true，设置后重启会话生效），放行后目录外路径仅告警不拦截（用户显式意图）。
- **破坏性清理门禁**：`cleanup(include_config=True / include_models=True)` 默认拒绝（删 key/cookie/模型不可逆）；`VIDEONOTE_ALLOW_DESTRUCTIVE_CLEANUP=1`（或插件 `allow_destructive_cleanup`=true）放行——放行后仍受「无运行中任务 / 无模型下载中 / 目标都在数据根内」三层守卫约束。
- 判断按 `resolve()`（符号链接跟随）时所在位置：数据目录内软链到外部同样按外部路径拒绝。

## 视频理解（画面切片）

把视频画面按时间间隔切片发给**多模态 LLM** 做「看画面」的理解（复用上游同一套 VideoReader）：

```text
generate_note(video_url=..., provider_id="qwen", model_name="qwen-vl-plus",
              video_understanding=True, video_interval=6, grid_size=[3, 3])
```

- **流程**：下载视频 → 每 `video_interval` 秒抽一帧 → 按 `grid_size` 拼成网格图 → 转 base64 data URI → 以 OpenAI 多模态 `image_url` 数组发给 LLM（图片内嵌在请求里，无需外网可访问地址）。
- **必须用多模态模型**：qwen-vl / gpt-4o 等；deepseek-chat 等纯文本模型不支持，会退回纯文本。
- `video_interval` 缺省 6 秒；`grid_size` 缺省自动 `[3, 3]`（`screenshot` 模式为 `[2, 2]`）。
- **默认值可在 setup ③ 配置**（默认关 / 6s）：agent 未显式传时自动套用；用户说「手动」再问本次是否启用。
- 注意：视频理解会**下载整个视频**并抽帧，比纯音频转写慢且占磁盘；`video_interval` 越大越省。
- 想要 markdown 里按 `*Screenshot-mm:ss` 标记插**单张**截图，用 `format=["screenshot"]`（区别于整片帧网格）。

## 整合弹幕+评论区观点

把 B 站**弹幕**和**评论区**的高频观点也整理进笔记（哪些弹幕刷屏、评论区在聊什么），`generate_note` 加：

```text
generate_note(video_url=..., ..., include_comments=True, comments_limit=20)
```

- 整合弹幕+评论区观点，让笔记不仅来自音轨，还能反映观众讨论；
- **笔记会新增一节「观众观点」**：总结弹幕刷屏/评论区反复出现的观点、补充、纠错（引用实际内容，不捏造）；无可总结时写「（无）」；
- `comments_limit` 控制抓取的评论条数（默认 20）；
- **需 B 站 SESSDATA**（登录态）：没配则评论拿不到 —— 先 `! videonote login bilibili` 扫码（或 setup 向导 Cookie 步骤）；**Cookie 一律走 CLI**；
- **抓取失败不阻断任务**：拿不到评论/弹幕时笔记照常生成，跳过该部分即可；
- 单独拉数据看 → 无独立工具（#135 精简）；弹幕/评论注入走 `generate_note` 的 `include_comments=True`；
- **默认值可在 setup ③ 配置**（默认关 / 20 条）：agent 未显式传时自动套用；用户说「手动」再问本次是否整合。

## 图片插入（便携笔记 Assets）

`format=["screenshot"]`（配合 `screenshot=True` 让 LLM 生成 `*Screenshot-[mm:ss]` 标记）会把标记替换成截图，并产出**便携笔记**：

```text
generate_note(video_url=..., ..., screenshot=True, format=["screenshot"])
```

- 结果：`note_dir/note.md` + `note_dir/Assets/*.jpg`，markdown 用**相对引用** `![...](Assets/xxx.jpg)`，整个文件夹可整体搬迁；
- 任务结果里 `result.note_dir` 指向该目录（agent 据此告诉你笔记位置、读图以它为基准）；
- **保存位置**优先级：
  1. `generate_note(..., notes_dir="/你/指定/的目录")`；
  2. 环境变量 `VIDEONOTE_NOTES_DIR`；
  3. 默认 `note_results/{task_id}/`。
- **指定 `notes_dir` 时每篇笔记一个文件夹**：`<notes_dir>/<笔记标题>/note.md`（标题取 LLM 生成的笔记 H1，回退视频标题；同名冲突自动加短 task_id 后缀）—— 多篇互不覆盖，且即使不插图片也会写文件。
- 与视频理解搭配更自然（`video_understanding=True` 时画面分析 + 截图都基于同一次视频下载）。

## 存储结构与清理

**每任务一个文件夹** `note_results/{task_id}/`（数据层重构后）：

```
{task_id}/
  raw/      ← 下载的原始材料（音频/视频/字幕/封面）
  gen/      ← 生成材料（transcript.json / note.md / Assets/ 截图 / frames/ 帧 / 导出 srt·vtt·json）
  status.json / result.json / manifest.json   ← 控制文件
```

**跨任务转写缓存** `<数据目录>/note_cache/`：同一视频（`platform:video_id`，B 站含分 P）再次 `generate_note` / `prepare_note_material` 时复用上次转写，**不再重下 + 重转写**。转写按来源分键（平台字幕 `subtitle` / 引擎+模型尺寸），切换转写引擎或模型尺寸不会误用旧结果；音频媒体也一并缓存，命中时复制到新任务（`audio_path` 指向真实文件）。默认 **30 天滑动 TTL**（命中刷新）+ **2048MB 总量上限**（按视频身份 LRU 淘汰）；`VIDEONOTE_CACHE_TTL_DAYS=0` / `VIDEONOTE_CACHE_MAX_MB=0` 关闭对应限制。按任务 `cleanup` 不碰缓存，全局 `cleanup` 连缓存一起清。

**全局任务索引**在 SQLite `video_tasks` 表（含 `title/status/summary/note_dir`），`list_tasks()` 枚举全部任务并带语义标题。

**数据库迁移边界（#149）**：兼容旧 schema 的迁移只对 SQLite 执行；新库/缺失 `video_tasks` 表由 `create_all` 建表，`_migrate_video_tasks` 对缺表安全 no-op。迁移本身若失败会记录并重新抛出，启动不会带着未知旧 schema 继续运行。

清理（agent 或 setup ④ 数据管理都可操作）：

- **先查后清**：`list_tasks()` 看全部任务（带标题）→ `cleanup(task_id, dry_run=True)` 看单个任务占哪些文件（返回 `{task_id, manifest_paths, existing, meta}`，不删任何东西）。
- **按任务清理**：`cleanup(task_id, include_note=False)` —— 以任务文件夹为边界。
  - `include_note=False`（默认）：删 `raw/` + `gen/` 内除 `note.md` 外的一切，**保留最终笔记 + 控制文件**；
  - `include_note=True`：删整个 `{task_id}/` 文件夹（含 manifest）+ 全局索引记录。
- **全局清理（恢复出厂）**：先 `cleanup(dry_run=True)` 预览将清理/保留项与运行中任务，确认后 `cleanup(include_config?, include_models?)` 执行 —— 清空 `note_results/*`、`static/screenshots/*`、`note_cache/*` + 清空全局索引。**`logs/` 不清**（运行日志不属任务产物，且 MCP 进程持有 log 打开 fd，unlink 会进已删除 inode）。
  - **默认保留** `config/`（LLM key / cookie / 转写设置）与 `models/`（已下载模型可复用、重下成本高）；
  - `include_config=True` 连 `config/` 一起清；`include_models=True` 连 `models/` 一起清；
  - **数据根外不删**（#140 安全红线）：`VIDEONOTE_CONFIG_DIR` / `VIDEONOTE_MODEL_DIR` 指向数据根外（或符号链接到外部）时拒绝清理，路径列入响应 `kept_outside`——与便携笔记副本同口径，只清数据目录内。
- **setup ④ 数据管理**：`videonote setup` 里选「④ 数据管理」——列任务（task_id | 标题 | 状态）、清理单个任务（确认保留/连笔记）、全局清理。
- **安全**：以任务文件夹为边界，删除前 `resolve()` 校验在 `NOTE_OUTPUT_DIR` / `DATA_DIR` 内（防路径穿越）；删除失败逐条跳过并返回统计（`deleted/missing/errors`）。manifest 写入的 `RLock` 只串行化同一 MCP 进程内的读-改-写，跨进程检查与删除之间的 TOCTOU 仍属于受信任本机目录之外的 P2 风险。

## 输出格式

笔记/转写产出后，可按需导出为多种格式。**分工**：

- **机械格式**（SRT/VTT/JSON）：确定性渲染（时间轴换算），由工具 `process_media(action="export", task_id=..., formats=["srt","vtt","json"], out_dir?)` 或 CLI `videonote export export <task_id> [--out-dir]` 直接产出，**不耗 LLM**，返回 `file://` 路径。**缺省输出目录**是该任务 `note_results/{task_id}/gen/`；CLI `--out-dir` 可指定桌面等任意目录。MCP `process_media` 的 `out_dir` 仍受数据目录门禁（`VIDEONOTE_ALLOW_EXTERNAL_PATHS`）。任务成功后若 setup ③ 配置了「导出格式默认」，会自动导出这些格式。
- **创意格式**（思维导图/闪卡/LaTeX/typst/用户自定义模板）：由 **Agent 基于 MD 底稿生成**，不调用 MCP 的确定性导出器。用户可提供自己的模板；仓库不再附带 LaTeX/Typst 模板，需要旧模板时从 Git 历史恢复并遵守对应许可证。编译 PDF 需用户自行安装 `xelatex` / `typst` 等工具。

## 音频增强（多文件合并 / 预处理 / 说话人分离）

- **平台覆盖**：内置 bilibili/youtube/douyin/tiktok/kuaishou/xiaoyuzhou/xiaohongshu/本地文件之外，`inspect_video` 返回 `platform:"generic"`，自动走 **yt-dlp 通用提取**（覆盖 1800+ 站点）；仍失败（登录墙/JS 渲染）才交给 Agent 接手。小宇宙有官方文稿时优先走平台文稿（需 `videonote login xiaoyuzhou`），否则回退 yt-dlp 音频 + 本地 ASR。小红书走原生笔记页解析（需登录时 `videonote login xiaohongshu`），无官方字幕则 ASR。抖音遇登录墙时先 `videonote login douyin`。
- **多文件合并**：`process_media(action="merge", files=..., out_dir?)` —— 把多段录音/会议分段/多个本地视频合并为一个 16kHz mono wav（FFmpeg concat，自动统一转码），再转写/总结。
- **音频预处理**（setup ② 勾选或 `videonote transcriber preprocess on`）：转写前把音频归一化为 16kHz mono wav；超长音频（>1800s）自动分块转写并拼接。**默认关**；零额外依赖（FFmpeg）。预处理的 `probe_duration` 是 best-effort：ffprobe 失败返回 0，分块时间偏移回退 1800 秒并记录 warning；这不同于 VideoReader 的严格时长探测。
- **VideoReader 时长探测**：视频理解/抽帧使用独立 ffprobe，120 秒超时，NaN、Inf、负数或无法解析直接报错，不应与预处理的 0 秒回退混为一谈。
- **说话人分离**（setup ② 勾选或 `videonote transcriber diarization on`）：`process_media(action="diarize", audio_file=..., num_speakers?)` 用 pyannote 给转写标说话人（会议纪要/多人口播）。**拒绝 `hf_token` 参数**（token 走 `HUGGINGFACE_HUB_TOKEN` / `! videonote setup`）。**可选重依赖**：需 `pyannote.audio` + torch + HF token + 在 huggingface.co 同意模型授权；未装时返回安装指引。

## Agent 工作流

一次典型的「给视频做笔记」：**默认由当前对话 Agent 写笔记**，不要先问模式。

1. `health_check(need_provider=False)` —— ffmpeg/db；**不要**因为 `keyed_providers=0` 去要 API key。
2. `inspect_video`（识别平台 + 检查链接 + 拆多集）。
3. `prepare_note_material`（能看图时开 `video_understanding` 抽帧）。
4. `task` 轮询到终态。
5. `task(action="transcript")` + Read `frames` → **你写 Markdown**。有弹幕/评论加「观众观点」。
6. **不要主动问后续优化**；用户要精修再改。

**后备 LLM**（仅当你无法看图，或用户明确要求配置 LLM）：`health_check(need_provider=True)` → 单集 `generate_note` / 合集 `batch_generate_notes` → 呈现 `result.markdown`。

用户明确说「手动 / 我要选参数」才逐项问。合集默认逐条 `prepare_note_material`（admission 默认 3）；互相独立的多个链接用 subagent。不要同一消息里并行多个 `generate_note` / `prepare_note_material`。

示例：

> 用户：帮我给这个视频做个笔记 https://www.youtube.com/watch?v=xxxx
>
> agent：`inspect_video` → `{ok:true, platform:"youtube", kind:"single"}`；`prepare_note_material` → 轮询 → 读转写/帧 → 写 Markdown。

## 手动模式 + 后备 LLM

- **默认**：当前 Agent 写笔记；`health_check` 默认不查供应商。
- **手动**（用户要求）：再问风格、视频理解、评论、截图（后备路径再问模型）。
- **后备 LLM**（无法看图 / 用户要求配置 LLM）：`generate_note` 或合集 `batch_generate_notes`。`agent_direct` 配置键 server 不读。

## 无 Skills 使用与历史恢复

MCP 工具自行提供参数和工作流描述；当前 Agent 可直接调用预检、素材、转写、生成及任务工具。上面的流程不依赖额外安装文件。

仓库已删除原 `skills/`（包括参考文档、LaTeX/Typst 模板）和 `commands/`。需要恢复时，先用 `git log --all -- skills/` 找到删除提交，再从该提交的父版本读取文件，例如 `git show <删除提交>^:skills/videonote/SKILL.md`。不创建或维护 Skills 备份分支；历史示例仅记录当时行为，不是当前安装要求。

`health_check` 的 `skill_refresh` 字段为兼容旧客户端保留，值为空串，不再要求刷新 Skills。

## 安全（API Key）

**红线：不要在对话里把 key 发给 agent。** agent 的对话内容会发送到它的 LLM 上游，key 一旦出现在对话里就等于交给了上游。**key 一律在独立终端走 CLI**（`!` 前缀的命令文本也在对话里，同样不行）：

```bash
videonote providers set deepseek --api-key 'sk-你的key'      # 独立终端执行
videonote providers list                                     # 查看（key 掩码）
```

- **agent 只需要知道「key 填没填」**：`get_config()` 的 `providers` 返回掩码（`sk-S***cdef`），相关日志已打码。
- **存哪**：key 只存在本地 SQLite（`~/.local/share/videonote-mcp/video_note.db` 或源码 `data/`），已 gitignore，**不会进 GitHub**。
- **加密**：落盘前经 Fernet 加密（机器本地密钥 `config/fernet.key`，权限 0600，见 `videonote_mcp/crypto.py`）；`providers` / `app_config` 读写自动加解密，DB 里看不到明文。本机密钥随数据目录持久化（卸载/升级不丢，符合设计红线），换机器不迁移密钥则读不出（需重填）。

## 开发版（dev 分支尝鲜）

开发版也直接使用 MCP，无需切换 Skills 或 marketplace：

```bash
# 先核对已有同名 MCP 配置；已有时再手动移除/替换，不要重复注册
claude mcp add --scope user videonote -- uvx --from git+https://github.com/HuangYincan/VideoNote-MCP@dev videonote
```

- 已有 MCP 的 JSON 配置中，把 args 改为 `["--from", "git+https://github.com/HuangYincan/VideoNote-MCP@dev", "videonote"]`，然后重启/重连。
- 回到 PyPI 稳定版：command 为 `uvx`，args 为 `["videonote@latest"]`；这不是未发布的 Git main。
- CLI 配置同版本：`uvx --from git+https://github.com/HuangYincan/VideoNote-MCP@dev videonote setup`。
- 默认安装包数据目录共用 `~/.local/share/videonote-mcp/`；源码默认 `<仓库>/data/`。客户端与扫码 CLI 必须使用同一数据/配置目录，本地未发布修复需客户端直接指向源码，不能只切换扫码命令。

## 故障排查

| 现象 | 原因 / 解决 |
|------|-------------|
| `health_check` 显示 `ffmpeg: missing` | 安装 FFmpeg（`brew install ffmpeg`）后重启 |
| `get_config()` 里某供应商 key 为空 | 在独立终端 `videonote providers set <id> --api-key '...'` |
| 提示"不支持的转写器" | `get_config()` 查看 transcriber 段，`! videonote transcriber set --engine fast-whisper` 改回 |
| whisper 转写时报模型未下载 | `! videonote transcriber download small` 后重试，或切 `groq` |
| `generate_note` 报"供应商不存在" | 先用 CLI 配好供应商与 key（`! videonote providers set <id> --api-key ...`），再 `get_config(provider_id)` 探测确认模型，把正确 `provider_id`/`model_name` 传入 |
| 首次转写卡在 `INITIALIZING` | 正在下载 whisper 模型，耐心等；模型大可改用云端转写 |
| `inspect_video` 返回 `platform:"generic"` | 内置平台之外自动走 yt-dlp 通用提取（覆盖 1800+ 站点）；仍失败（登录墙/JS）才需 Agent 接手 |
| 小宇宙走了很久本地转写 | 未配登录态，官方文稿拿不到。让用户 `! videonote login xiaoyuzhou` 后重试（有文稿则跳过 ASR） |
| 小红书下载失败 / 图文笔记 | 图文笔记无法转写。视频笔记遇登录墙让用户 `! videonote login xiaohongshu` 后重试（需本机 Chrome/Edge；没有就 `--cookie`）。`inspect_video` 应返回 `platform:"xiaohongshu"` |
| 小红书扫码报 HTTP 406 | 旧版直连接口已被拒。升级后扫码改走本机 Chrome 打开官网。请安装 Google Chrome 后重试，或 `--cookie` 粘贴 |
| 抖音下载失败 / 登录墙 | 先区分旧版预检、msToken 初始化或详情请求失败与明确登录墙；已保存 Cookie 时不要仅凭未知错误重复扫码。核对 MCP 版本及数据/配置目录，确认缺少登录配置或明确认证失效后再运行 `! videonote login douyin`（需本机 Chrome/Edge；没有就 `--cookie`）。`inspect_video` 应返回 `platform:"douyin"` |
| 抖音精选页 / App 短链解析失败或每次重转写 | 同一条视频的 `/video/{id}`、`/jingxuan?modal_id={id}`、`v.douyin.com/...` 会归一为同一 aweme_id。升级后重试 |
| 抖音扫码报「生成二维码失败: HTTP 200」/ 风控页 | 直连接口已被风控。升级后扫码改走本机 Chrome 打开官网。请安装 Google Chrome 后重试，或 `--cookie` 粘贴 |
| 抖音扫码后手机已确认，CLI 一直「已扫码」 | 查看电脑上的抖音登录窗口是否要求「身份验证」。修复版显示浏览器，识别二次验证响应（2046），暂停后备轮询并单独等待最多 5 分钟；请本人完成短信/刷脸后等待 CLI 保存登录态。旧版隐藏窗口且忽略此响应。无桌面环境用 `--cookie` |
| 抖音浏览器已登录，却提示「登录态无效或未能确认」 | 旧校验把非 JSON / 未识别的响应也当成登录无效。修复版区分「已保存 Cookie」与「附加校验未能确认」，显示 HTTP 状态或短数字错误码，不清除已保存凭证。可先尝试下载，不必仅因此重新扫码；这也不保证下载接口一定可用 |
| 抖音二维码很快失效 / 手机扫了终端无反应 | 以终端剩余秒数为准，官网可能只给约 60 秒；过期或自动换码后重新运行。修复版按真实时间计时，不再用固定 90 次循环 |
| `process_media`（diarize）报需安装/缺 token | pyannote 可选重依赖：`transcriber diarization on` 引导安装 + 配 HF_TOKEN + 同意模型授权 |
| 任务长时间卡住 | `task` 看 message；可能视频很长或模型下载中，耐心等待或换小模型 |
| 中文乱码/内容差 | 检查所选模型能力；`style` 会影响输出格式 |
