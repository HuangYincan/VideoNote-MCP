# 04-使用手册

> 本手册面向两种读者：**人类用户**（如何安装、配置、调试）与 **agent**（如何调用这套 MCP 工具完成"生成视频笔记"）。快速上手见 [README](../README.md)，本手册是详细参考。

## 前提

- **uv**（Python 包管理器，必需）：`curl -LsSf https://astral.sh/uv/install.sh | sh` 或 `brew install uv`（没有 uv 走[安装方式四](#安装)，脚本内置 pip 兜底）
- **Python ≥ 3.11，<3.14**（推荐 3.12）
- **FFmpeg**：`brew install ffmpeg`（Linux：`apt install ffmpeg`）
- **LLM 供应商 API Key**（见[配置](#配置装完必做)）
- **本地转写**：本地 whisper 需先 `videonote transcriber download <size>`，或改用云端 `groq` / `bcut`
- **GPU 加速（可选）**：NVIDIA/Linux 想用 CUDA → 装工具时 `--with torch`（whisper 自动检测 GPU，默认 CPU）；macOS Apple Silicon → `--with mlx-whisper` + `videonote transcriber set mlx-whisper`
- **CLI 命令简写**：正文里的 `videonote ...` 等价于：
  - 有 uv：`uvx --from git+https://github.com/HuangYincan/VideoNote-MCP videonote ...`（`--from` 必须带 `git+` 前缀）
  - 源码（方式四）：`<仓库路径>/.venv/bin/videonote ...`

## 安装

安装方式详见 [README 快速开始](../README.md#快速开始)，四种任选：

| 方式 | 命令 | 说明 |
|------|------|------|
| 一 · 插件 marketplace（推荐） | `claude plugin marketplace add HuangYincan/VideoNote-MCP` + `claude plugin install videonote@videonote` | Skill + MCP，uvx 自动更新 |
| 二 · 只装 MCP | `claude mcp add --scope user videonote -- uvx --from git+https://github.com/HuangYincan/VideoNote-MCP videonote` | 仅 MCP |
| 三 · uv tool install | `uv tool install --from git+https://github.com/HuangYincan/VideoNote-MCP videonote` + `claude mcp add videonote -- "$HOME/.local/bin/videonote"` | 固定版本、启动最快 |
| 四 · 克隆 + install.sh | `git clone https://github.com/HuangYincan/VideoNote-MCP.git && cd VideoNote-MCP && ./install.sh` | 无 uv 兜底，自动弹 setup |

装完**必须重启** Claude Code 会话（或 `/reload-plugins`）才会加载插件的 MCP server —— **重启前不要跑 `/videonote-setup`**（MCP 工具未挂载，命令会停在诊断步）。**方式一（marketplace）的 MCP 由插件提供**，`claude mcp list` 不会列出它（插件 server 独立注册）；重启后在会话里直接可用工具、或跑 `/videonote-setup` 验证。方式二/四（用户级 `claude mcp add`）`claude mcp list` 会显示 `videonote`。

> [!WARNING] 混合安装注意
> 若此前用「方式二」或旧版 `install.sh` 加过**用户级** `claude mcp add videonote`，该条目 `env` 为空，会**遮蔽插件自带 MCP server 的 env**（`/plugin` 安装时填的 userConfig 默认值不生效）。用 `claude mcp remove videonote` 移除，让插件 server 接管（命令相同 `uvx --from ...@dev videonote`、同数据目录，无功能损失）。新装请直接走**方式一**，不要再手动 `claude mcp add`。

## 配置（装完必做）

> 所有方式共用同一数据目录（`~/.local/share/videonote-mcp/`），配好即会话内生效。

### 插件方式（方式一安装，装完在 Claude Code 里配置）

`/plugin install` 时 Claude Code 会**逐项提示填默认值**（笔记风格 / 转写引擎 / 模型尺寸 / 视频理解 / 评论弹幕 / 笔记位置，均非敏感）——存 Claude Code 配置，经 MCP `env` 注入 server，作为「配置文件缺项时的兜底默认」（配置文件优先，之后跑 `setup` 向导修改仍以向导为准）。

**填法**（`/plugin configure` 页**全部为键盘输入**，无下拉/开关）：布尔项（插图/视频理解/评论）输入 `true`/`false`；目录项（笔记位置）输入**绝对路径**，留空 = 默认；字符串项（风格/引擎/尺寸）直接输入英文 key —— 风格 `detailed`/`minimal`/`academic`/`tutorial`/`xiaohongshu`/`life_journal`/`task_oriented`/`business`/`meeting_minutes`；引擎 `fast-whisper`/`groq`/`bcut`/`kuaishou`/`mlx-whisper`；尺寸 `tiny`/`base`/`small`/`medium`/`large-v3`/`large-v3-turbo`。Configure 页每个字段下方的说明也列出了可填值。

装完在会话里跑 **`/videonote-setup`** 收尾：体检 → 引导填 key → 转写模型下载 → 展示默认值 → B站扫码 → 数据管理。

> **凭证红线**：LLM key / SESSDATA 一律走 `!` 前缀在**本会话终端**输入（隐藏输入、值不过 agent 对话），或独立终端跑完整命令。下面的命令在本会话用 `! videonote ...` 前缀即可直接跑。

### 交互向导 `setup`（推荐，随时可反复进入修改）

```bash
videonote setup
```

**方向键选择 + 高亮**、**左键返回上一级**、每步自动清屏；**不是一次性程序**，随时重跑即可改配置：① LLM 供应商（填/改 key、新增中转站、**检测连接 / 列模型 / 设默认模型**）→ ② 转写引擎 + 模型尺寸（未下载会提示下载）→ ③ 平台 Cookie（下拉选择）/ 默认笔记位置（持久化）/ **视频理解默认**（开/关 + 帧间隔秒数，持久化）/ **评论/弹幕整合默认**（开/关 + 评论条数，持久化，需 B 站 SESSDATA）/ **笔记默认**（`default_style` 默认 detailed、`default_screenshot` 默认关、`agent_direct` 默认关，持久化）—— **全自动模式**套用这些默认（会先列出完整参数清单给用户确认）。

### LLM 供应商（key 走 CLI，对话外）

内置供应商（openai / deepseek / qwen / groq / ollama…）在空库时已自动预置，id 固定、base_url 正确，**只需填 key**：

```bash
# 终端（key 不进对话；本会话里用 `!` 前缀，如 `! videonote providers list`）
videonote providers list                                  # 看内置供应商，key 为空
videonote providers set deepseek --api-key 'sk-你的key'     # 填 key（掩码回显）
videonote providers test deepseek                          # 检测连接 + 列出可用模型
videonote providers test deepseek --default deepseek-chat   # 检测并设为默认模型
```

**检测连接 / 设默认**：`setup` 向导里选中某供应商会进入「管理」子菜单（✏ 编辑 key/base_url / 🔌 检测连接 → 列出模型 → 设默认 / ← 返回）。检测用 OpenAI 兼容 `GET /v1/models`（一次验证 key/base_url 并拿到模型列表）；`/v1/models` 不可用（部分中转站/自建网关）时降级为「最小对话请求」chat 探测。默认模型持久化在 `config/app_config.json`（`default_model:{provider_id}`）—— `generate_note` **未指定 `model_name` 时优先用配置的默认模型**，再退 DB 第一条。

```text
# agent 侧（只做非敏感操作）
list_providers()                            # deepseek key=已填（掩码，看不到明文）
list_models("deepseek")                     # 实时拉 /v1/models；失败回退本地库
add_model(provider_id="deepseek", model_name="deepseek-chat")   # 实时拉不到时手动加
```

**中转站 / 自建网关**（非内置）：终端新增

```bash
videonote providers add --name 我的中转站 --api-key 'sk-中转站发的key' --base-url 'https://relay.example.com/v1'
videonote providers list                                    # 记下新供应商 id
```

**没有 LLM key？** 本地装 [Ollama](https://ollama.com) 并 `ollama pull llama3`，内置 `ollama` 供应商**无需 key**，`list_models("ollama")` 有模型即可用；或注册 Groq/DeepSeek 免费额度后 `providers set` 填 key。

### 转写引擎

**终端直接切换（推荐，非交互）：**

```bash
videonote transcriber list                          # 查看当前引擎与就绪状态
videonote transcriber set fast-whisper --size small  # 切本地 whisper
videonote transcriber download small                  # 下载 fast-whisper 模型
videonote transcriber download small --engine mlx-whisper  # 下载 mlx-whisper（macOS）

# B 站：优先用平台字幕（含 AI 字幕）跳过语音识别；AI 字幕需登录态
videonote login bilibili     # 扫码登录，二维码渲染进终端/会话，自动保存 SESSDATA
videonote transcriber set groq                        # 切云端
```

**引擎**：`fast-whisper`（本地）/ `groq` / `bcut` / `kuaishou`（云端）/ `mlx-whisper`（**仅 macOS Apple Silicon**，GPU 加速）/ `funasr`（**中文最优**：Paraformer-zh + VAD + 自动标点）。
**whisper 尺寸**：`tiny` / `base` / `small` / `medium` / `large-v3` / `large-v3-turbo`（turbo 更快、精度略低）。
**设备**：whisper 自动检测 CUDA（有 torch+CUDA 用 GPU，否则 CPU）；macOS 用 `mlx-whisper` 走 Apple Silicon GPU。CLI `download` 用 CPU 只是下载权重、不推理。
**funasr（可选重依赖）**：中文转写质量优于 faster-whisper，自带 VAD 分段 + 中文标点。需 `uvx --with funasr --with torch` 安装；模型首次转写时自动下载（无需 `download` 命令）。未装时 `set_transcriber("funasr")` 返回安装指引。

**或 agent 侧用工具：**

```text
get_transcriber_config()           # 当前：fast-whisper / tiny

# 本地离线转写（推荐，免费）：切引擎 + 下载对应尺寸模型
set_transcriber("fast-whisper", "small")
download_transcriber_model("small")            # 后台下载；list_transcriber_models 看到 state=done 即就绪

# 云端转写（快、省资源，需 key）：先在独立终端填 key，再直接切
#   独立终端：videonote providers set groq --api-key 'gsk-你的key'
set_transcriber("groq")
get_transcriber_config()           # ready=true 即就绪
```

> whisper 模型尺寸（约）：tiny 75MB / base 145MB / small 460MB / medium 1.5GB / large-v3 3GB。够用选 small 及以下，追求精度再上 medium+。
> macOS Apple Silicon 可用 MLX Whisper（`set_transcriber("mlx-whisper", "small")`），需安装时带 `--with mlx-whisper`。

### 平台 Cookie（B 站等）

部分平台需登录 Cookie 才能下载高清/完整内容：

```text
set_downloader_cookie(platform="bilibili", cookie="SESSDATA=...")
```

## 环境变量（可选）

| 变量 | 作用 | 默认 |
|------|------|------|
| `VIDEONOTE_DATA_DIR` | 数据根目录（SQLite / 笔记 / 截图 / 配置） | 安装模式 `~/.local/share/videonote-mcp`，源码 `仓库/data` |
| `VIDEONOTE_NOTES_DIR` | 默认笔记输出目录（指定 `notes_dir` 时的兜底） | `note_results/{task_id}/` |
| `VIDEONOTE_CONFIG_DIR` | 配置文件目录（转写/cookie/app 配置） | `<数据目录>/config` |
| `VIDEONOTE_MODEL_DIR` | whisper / mlx 模型目录 | `<数据目录>/models`（源码 `仓库/models`） |
| `VIDEONOTE_MAX_WORKERS` | 单个 MCP 会话内**并发笔记任务数** | 3 |
| `HF_ENDPOINT` | HuggingFace 镜像（国内下载慢/卡时用） | 官方 `https://huggingface.co`；国内可 `https://hf-mirror.com` |

**会话内串行 + 多会话并行**：每个 Claude Code 会话独立起一个 MCP server 进程。**本会话内任务强制串行** —— `generate_note` 在已有进行中任务时会**直接拒绝**（必须一次一个：提交 → 等到 `SUCCESS`/`FAILED`/`CANCELLED` → 再提交下一个）；**多个会话**可各自并行生成不同视频的笔记（互不干扰）。**注意**：Claude Code 客户端对「同一条消息里多个并行 MCP 工具调用」处理不稳（最后一个响应会卡死、任务也未提交）—— 所以即使跨任务，也**不要在同一消息里并行塞多个 `generate_note`**。**多任务轮询请用轻量 `get_task_status(task_id)` 快照轮询**；`wait_for_note` 是阻塞调用，会卡住当前轮次。需要取消进行中任务用 `cancel_note(task_id)`。注意：whisper / MLX 转写吃 CPU/内存，太多会话并行会拉满机器；所有会话共用同一个 SQLite，极端并发下可能偶发写冲突。

## 视频理解（画面切片）

把视频画面按时间间隔切片发给**多模态 LLM** 做「看画面」的理解（复用上游同一套 VideoReader）：

```text
generate_note(video_url=..., provider_id="qwen", model_name="qwen-vl-plus",
              video_understanding=True, video_interval=6, grid_size=[3, 3])
```

- **流程**：下载视频 → 每 `video_interval` 秒抽一帧 → 按 `grid_size` 拼成网格图 → 转 base64 data URI → 以 OpenAI 多模态 `image_url` 数组发给 LLM（图片内嵌在请求里，无需外网可访问地址）。
- **必须用多模态模型**：qwen-vl / gpt-4o 等；deepseek-chat 等纯文本模型不支持，会退回纯文本。
- `video_interval` 缺省 6 秒；`grid_size` 缺省自动 `[3, 3]`（`screenshot` 模式为 `[2, 2]`）。
- **默认值可在 setup ③ 配置**（默认关 / 6s）：agent 未显式传 `video_understanding` / `video_interval` 时自动套用；**手动模式下 SKILL 仍要求先问用户**本次是否启用 + 间隔，只有用户说「你定/用默认」才用默认值；**全自动模式**套默认（先列出参数清单待确认）。
- 注意：视频理解会**下载整个视频**并抽帧，比纯音频转写慢且占磁盘；`video_interval` 越大越省。
- 想要 markdown 里按 `*Screenshot-mm:ss` 标记插**单张**截图，用 `format=["screenshot"]`（区别于整片帧网格）。

## 整合弹幕+评论区观点

把 B 站**弹幕**和**评论区**的高频观点也整理进笔记（哪些弹幕刷屏、评论区在聊什么），`generate_note` 加：

```text
generate_note(video_url=..., ..., include_comments=True, comments_limit=20)
```

- 整合弹幕+评论区观点，让笔记不仅来自音轨，还能反映观众讨论；
- **笔记会新增一节「观众观点」**：总结弹幕刷屏/评论区反复出现的观点、补充、纠错（引用实际内容，不捏造）；无可总结时写「（无）」；
- `comments_limit` 控制抓取的评论条数（默认 20）；
- **需 B 站 SESSDATA**（登录态）：没配则评论拿不到 —— 先 `videonote login bilibili` 扫码（或 `set_downloader_cookie(platform="bilibili", cookie="SESSDATA=...")`）；
- **抓取失败不阻断任务**：拿不到评论/弹幕时笔记照常生成，跳过该部分即可；
- 只想单独拉数据看，用 `fetch_comments(video_url, limit=20)` / `fetch_danmaku(video_url)` 两个工具；
- **默认值可在 setup ③ 配置**（默认关 / 20条）：agent 未显式传 `include_comments` / `comments_limit` 时自动套用；**手动模式下 SKILL 仍要求先问用户**本次是否整合，只有用户说「你定/用默认」才用默认值；**全自动模式**套默认（先列出参数清单待确认）。

## 图片插入（便携笔记 Assets）

`format=["screenshot"]`（配合 `screenshot=True` 让 LLM 生成 `*Screenshot-[mm:ss]` 标记）会把标记替换成截图，并产出**便携笔记**：

```text
generate_note(video_url=..., ..., screenshot=True, format=["screenshot"])
```

- 结果：`note_dir/note.md` + `note_dir/Assets/*.jpg`，markdown 用**相对引用** `![...](Assets/xxx.jpg)`，整个文件夹可整体搬迁；
- 任务结果里 `result.note_dir` 指向该目录（agent 据此告诉你笔记位置、读图以它为基准）；
- **保存位置**优先级：
  1. `generate_note(..., notes_dir="/你/指定/的目录")`；
  2. 环境变量 `VIDEONOTE_NOTES_DIR`；
  3. 默认 `note_results/{task_id}/`。
- **指定 `notes_dir` 时每篇笔记一个文件夹**：`<notes_dir>/<笔记标题>/note.md`（标题取 LLM 生成的笔记 H1，回退视频标题；同名冲突自动加短 task_id 后缀）—— 多篇互不覆盖，且即使不插图片也会写文件。
- 与视频理解搭配更自然（`video_understanding=True` 时画面分析 + 截图都基于同一次视频下载）。

## 存储结构与清理

**每任务一个文件夹** `note_results/{task_id}/`（数据层重构后）：

```
{task_id}/
  raw/      ← 下载的原始材料（音频/视频/字幕/封面）
  gen/      ← 生成材料（transcript.json / note.md / Assets/ 截图 / frames/ 帧 / 导出 srt·vtt·json）
  status.json / result.json / manifest.json   ← 控制文件
```

**全局任务索引**在 SQLite `video_tasks` 表（含 `title/status/summary/note_dir`），`list_tasks()` 枚举全部任务并带语义标题。

清理（agent 或 setup ④ 数据管理都可操作）：

- **先查后清**：`list_tasks()` 看全部任务（带标题）→ `get_task_files(task_id)` 看单个任务占哪些文件（返回 `{task_id, manifest_paths, existing, meta}`）。
- **按任务清理**：`cleanup_note(task_id, include_note=False)` —— 以任务文件夹为边界。
  - `include_note=False`（默认）：删 `raw/` + `gen/` 内除 `note.md` 外的一切，**保留最终笔记 + 控制文件**；
  - `include_note=True`：删整个 `{task_id}/` 文件夹（含 manifest）+ 全局索引记录。
- **全局清理（恢复出厂）**：`cleanup_all(include_config=False, include_models=False)` —— 清空 `note_results/*`、`static/screenshots/*`、`logs/*` + 清空全局索引。
  - **默认保留** `config/`（LLM key / cookie / 转写设置）与 `models/`（已下载模型可复用、重下成本高）；
  - `include_config=True` 连 `config/` 一起清；`include_models=True` 连 `models/` 一起清。
- **setup ④ 数据管理**：`videonote setup` 里选「④ 数据管理」——列任务（task_id | 标题 | 状态）、清理单个任务（确认保留/连笔记）、全局清理。
- **安全**：以任务文件夹为边界，删除前 `resolve()` 校验在 `NOTE_OUTPUT_DIR` / `DATA_DIR` 内（防路径穿越）；删除失败逐条跳过并返回统计（`deleted/missing/errors`）。

## 输出格式

笔记/转写产出后，可按需导出为多种格式。**分工**：

- **机械格式**（SRT/VTT/JSON）：确定性渲染（时间轴换算），由工具 `export_transcript(task_id, formats=["srt","vtt","json"], out_dir?)` 直接产出，**不耗 LLM**，返回 `file://` 路径。任务成功后若 setup ③ 配置了「导出格式默认」，会自动导出这些格式。
- **创意格式**（思维导图/闪卡/LaTeX/typst/用户自定义模板）：由 **Agent 基于 MD 底稿生成**——底稿是信息源，Agent 读取后按目标格式重写。**LaTeX** 有内置模板（`skills/videonote/templates/latex/`：`Math Note/` 数学/理工科笔记、`English Article/` 英文文稿），用户选模板后 Agent 按 `main.tex` 生成 `.tex`（可选 `xelatex` 编译 PDF，Math Note 需随带 `MathNote.cls`/`MathNoteCN.cls`）；**typst** 有内置模板（`skills/videonote/templates/typst/zju-lab/`：理工科笔记/实验报告/论文风，带 ZJU 校徽），用户选模板后 Agent 按 `template.typ` 生成 `.typ`（可选 `typst compile` 编译 PDF，`@preview/*` 包自动拉取）；用户自带 typst/LaTeX 模板同样支持。模板来源与许可见 `templates/latex/NOTICE.md` 与 `templates/typst/zju-lab/README.md`，用法详见 SKILL 的 `reference/output-formats.md`。

## 音频增强（多文件合并 / 预处理 / 说话人分离）

- **平台覆盖**：内置 bilibili/youtube/douyin/tiktok/kuaishou/本地文件之外，`validate_url` 返回 `platform:"generic"`，自动走 **yt-dlp 通用提取**（覆盖 1800+ 站点）；仍失败（登录墙/JS 渲染）才交给 Agent 接手。
- **多文件合并**：`merge_audio(files, out_dir?)` —— 把多段录音/会议分段/多个本地视频合并为一个 16kHz mono wav（FFmpeg concat，自动统一转码），再转写/总结。
- **音频预处理**（setup ② 勾选或 `videonote transcriber preprocess on`）：转写前把音频归一化为 16kHz mono wav；超长音频（>1800s）自动分块转写并拼接。**默认关**；零额外依赖（FFmpeg）。
- **说话人分离**（setup ② 勾选或 `videonote transcriber diarization on`）：`diarize_media(audio_file, num_speakers?, hf_token?)` 用 pyannote 给转写标说话人（会议纪要/多人口播）。**可选重依赖**：需 `pyannote.audio` + torch + `HF_TOKEN` + 在 huggingface.co 同意模型授权；未装时返回安装指引。

## Agent 工作流

一次典型的"给视频做笔记"任务，agent 应按顺序调用：

1. `health_check` —— 确认 ffmpeg/db 就绪；
2. `list_providers` —— 确认有供应商且 key=已填（**没有就让用户用 CLI 配，agent 不碰 key**）；
3. `generate_note(video_url=..., provider_id=..., model_name=...)` —— 拿 task_id；
4. `get_task_status(task_id)` **轻量快照轮询**，等到 `SUCCESS`/`FAILED`/`CANCELLED`（**任务一次只发一个**，server 有进行中任务会拒绝新提交；不要并行塞多个 `generate_note`；`wait_for_note` 是阻塞调用）；
5. SUCCESS 后拿到 `result.markdown` —— **阅读该 Markdown 并用它回答用户的所有问题**（不要发明笔记里没有的内容）；
6. 若用户要的是"视频里某个细节"，可在 Markdown 之外用 **`get_task_transcript(task_id)`** 按需取转写（默认 `get_task_status` 轻量结果**不含**完整转写）辅助定位；
7. **问用户是否要根据笔记 + 提取的字幕做后续优化**（补齐遗漏、修正与字幕不一致处、增强结构）—— agent 读 `result.markdown` + `get_task_transcript(task_id)` 取回的转写自己精修（转写过长时用 `segment_range` 按章节精修并如实告知限制）。

示例对话：

> 用户：帮我给这个视频做个笔记 https://www.youtube.com/watch?v=xxxx
>
> agent：先问「全自动/手动」；`validate_url` → youtube；`list_providers` 确认供应商 key=已填；按模式确认参数 → `generate_note` → 轮询 → SUCCESS；展示 Markdown 并总结要点。

## 全自动 / 手动模式 + AGENT 直接生成

任务开始时 agent **会先问用户「全自动」还是「手动」**（SKILL 强制规则第 0 条）：

- **全自动**：用 setup ③ 的默认解析出**完整参数清单**（生成方式/LLM 模型（或选 AGENT 直接生成）/ `default_style`（默认 detailed）/ 视频理解默认 / 评论默认 / 截图默认 / **生成后是否后续优化**），**一次性列给用户确认**、不逐个问；用户要改某项再以提问方式改，确认后 `generate_note` 不传 style / screenshot / video_understanding / include_comments / agent_direct 即套默认。「AGENT 直接生成」在选 LLM 模型阶段提供（默认用配置 LLM）。适合「按已配好的默认跑」的日常任务。
- **手动**：逐个确认参数（LLM 模型、笔记风格、视频理解、评论/弹幕、截图、是否 AGENT 直接生成），确认完再生成。适合想精细控制每次输出时。

**AGENT 直接生成（`agent_direct`）**：在**选 LLM 模型阶段**提供选项 —— 手动模式问「用哪个模型，还是 AGENT 直接生成」；全自动模式默认用配置 LLM，可在参数清单里改选。开启后**不走配置的 LLM**，由 agent 自己写笔记：

1. `prepare_note_material(video_url, video_understanding?, video_interval?, include_comments?, comments_limit?)` → `task_id`；
2. `get_task_status(task_id)` 轮询到 `SUCCESS` → 拿**轻量素材**：`result.frames`（`file://` 抽帧图，多模态模型下用 Read 看图）、`result.video_path`/`audio_path`；转写文本用 **`get_task_transcript(task_id)`** 按需取（超长用 `segment_range` 分段），评论/弹幕用 `get_task_status(task_id, include_transcript=True)` 一次性取（连带完整转写，长视频慎用）；
3. agent 读转写 / 看图 → **自己写 Markdown**（问风格，默认 detailed；素材包里有 `comments_danmaku` 时笔记新增一节「观众观点」总结观众观点）→ 呈现。

转写可能很长（如 2h 视频超上下文）—— agent **按章节分段精修**或让用户指定重点。其余流程（health_check / validate_url / 轮询 / 后续优化）与常规一致。

## Skill 使用

仓库自带 Claude Code Skill（`skills/videonote/SKILL.md`），它教 agent 用上面的流程**一句话完成「视频 → 笔记」**（触发词：「生成视频笔记」「帮这个视频做笔记」「从 XX 链接做笔记」）。通过插件 marketplace 安装（同时装好 Skill 与 MCP server）：

```bash
claude plugin marketplace add HuangYincan/VideoNote-MCP
```

装完重启会话（或 `/reload-plugins`），之后在 Claude Code 里说「帮我给这个视频做笔记」+ 链接即可触发。

> Skill 更新（三步各有用）：`claude plugin marketplace update videonote`（拉最新 commit）→ `claude plugin disable videonote@videonote` → `claude plugin install videonote@videonote`（`install` 单独会被「已安装」跳过，必须先 `disable`；不 `marketplace update` 则拉的还是旧克隆）。

| 装的什么 | 更新命令 |

## 安全（API Key）

**红线：不要在对话里把 key 发给 agent。** agent 的对话内容会发送到它的 LLM 上游，key 一旦出现在对话里就等于交给了上游。**key 一律在独立终端走 CLI**（`!` 前缀的命令文本也在对话里，同样不行）：

```bash
videonote providers set deepseek --api-key 'sk-你的key'      # 独立终端执行
videonote providers list                                     # 查看（key 掩码）
```

- **agent 只需要知道「key 填没填」**：`list_providers` 返回掩码（`sk-S***cdef`），add/update 工具不回显 key，相关日志已打码。
- **存哪**：key 只存在本地 SQLite（`~/.local/share/videonote-mcp/video_note.db` 或源码 `data/`），已 gitignore，**不会进 GitHub**。
- **提醒**：key 以明文存在本地数据库（与上游一致）。若机器可能被他人使用，建议后续用系统 keychain 加密存储。

## 故障排查

| 现象 | 原因 / 解决 |
|------|-------------|
| `health_check` 显示 `ffmpeg: missing` | 安装 FFmpeg（`brew install ffmpeg`）后重启 |
| `list_providers` 里 key 为空 | 在独立终端 `videonote providers set <id> --api-key '...'` |
| 提示"不支持的转写器" | `get_transcriber_config` 查看，`set_transcriber` 改回 `fast-whisper` |
| whisper 转写时报模型未下载 | `download_transcriber_model(model_size="small")` 后重试，或切 `groq` |
| `generate_note` 报"供应商不存在" | 先用 CLI 配好供应商与 key，再 `list_models` / `add_model` 确认模型，把正确 `provider_id`/`model_name` 传入 |
| 首次转写卡在 `INITIALIZING` | 正在下载 whisper 模型，耐心等；模型大可改用云端转写 |
| `validate_url` 返回 `platform:"generic"` | 内置 5 平台之外自动走 yt-dlp 通用提取（覆盖 1800+ 站点）；仍失败（登录墙/JS）才需 Agent 接手 |
| `diarize_media` 报需安装/缺 token | pyannote 可选重依赖：`transcriber diarization on` 引导安装 + 配 HF_TOKEN + 同意模型授权 |
| 任务长时间卡住 | `get_task_status` 看 message；可能视频很长或模型下载中，耐心等待或换小模型 |
| 中文乱码/内容差 | 检查所选模型能力；`style` 会影响输出格式 |
