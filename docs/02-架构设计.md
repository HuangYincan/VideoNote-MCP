# 02-架构设计

## 总体数据流

```
视频链接 (URL / file:// / 本地路径)
   │
   ▼  ① detect_platform
      内置：bilibili / youtube / douyin / tiktok / kuaishou / xiaoyuzhou / xiaohongshu / local
      其它 URL → generic（yt-dlp 1800+ 站点）；仅显式 platform=unsupported 才 handoff
   │
   ▼  ② 下载（yt-dlp 适配器）或本地直读
音频 / 视频 + 元信息 → note_results/{task_id}/raw/
   │
   ▼  ③ 平台字幕优先（YouTube / B 站 / 小宇宙官方文稿）；无则转写
      引擎：fast-whisper / mlx-whisper / funasr / groq / bcut / kuaishou
      可选：预处理（16kHz 归一 + 超长分块）/ 说话人分离（经 `process_media` 调用）
      任务取消通过 `cancel_event` 在各阶段边界协作传播
TranscriptResult → note_results/{task_id}/gen/transcript.json
   │
   ▼  ④ LLM 总结（GPT 工厂，按 provider_id）或停在素材包
Markdown / material
   │
   ▼  ⑤ 后处理（截图、链接、源链接前缀、可选 SRT/VTT/JSON 导出）
   │
   ▼  ⑥ 落盘：note_results/{task_id}/{status.json, result.json, manifest.json, raw/, gen/}
      全局索引：SQLite video_tasks（list_tasks）
```

Agent 时序：`generate_note` 或 `prepare_note_material`（拿到 `task_id`）→ 轮询 `task`（默认 `action="status"`）→ 读 `result.markdown` / `task`（`action="transcript"`）。

## 异步任务与任务文件夹

- `generate_note` / `prepare_note_material` / `batch_generate_notes` 提交后由后台 `ThreadPoolExecutor` 异步执行：立即返回 `task_id`，再由 `task` 轮询。普通任务受 admission 限制并预占名额覆盖排队与执行；batch 通过 thread-local bypass 不占普通 admission 名额，由线程池排队。`inspect_video`、`health_check`、`get_config`、`list_tasks`、`process_media`、`cleanup` 为同步工具。
- `process_media` 是同步媒体加工入口，不创建后台任务、不登记 `_task_futures`/`_task_events`，因此没有对应 `task_id` 可供 `task(action="cancel")` 控制；第三方阻塞调用仍只能自然返回。
- 布局：`note_results/{task_id}/status.json` + `result.json` + `manifest.json` + `raw/` + `gen/`。**不是**扁平的 `{task_id}.json`。
- 状态枚举：`PENDING → INITIALIZING → PARSING → DOWNLOADING → TRANSCRIBING → SUMMARIZING → FORMATTING → SAVING → SUCCESS/FAILED/CANCELLED`。
- 未知 `task_id`（没有 `status.json`）返回 **`NOT_FOUND`**，不是 PENDING。
- 步骤任务也会 `insert_video_task`，`list_tasks` 能看见。
- `task`（status）默认剥掉完整转写；用 `task`（transcript）按需取。

## MCP 工具（10 个）

凭证红线：**API key / Cookie / HF token 不能经 MCP 工具传入**。填 key 走 `! videonote providers set`；B 站 Cookie 走 `! videonote login bilibili`；小宇宙官方文稿走 `! videonote login xiaoyuzhou`；小红书走 `! videonote login xiaohongshu` / `! videonote setup`。转写全文另可走 **MCP Resource** `videonote://task/{task_id}/transcript`（时间轴纯文本，不占工具数）。

**#135 工具精简（39→18）**：删除全部写配置工具（供应商/模型/转写器/Cookie CRUD——配置修改一律走 CLI，MCP 面零写配置入口）与流水线步骤工具（`fetch_*` / `transcribe_media` / `extract_frames` / `summarize_note`——端到端 `generate_note` 内部已含全部步骤，步骤工具暴露面冗余）。只读配置合并为单一 `get_config`。**#138 再精简（16→10）**：状态/转写/取消合并为单一 `task`（action 分派），清理合并为 `cleanup`，导出/合并/说话人分离合并为 `process_media`，`preflight` 并入 `health_check`。

| 分组 | 工具 | 要点 |
|------|------|------|
| 生成 | `generate_note` | `provider_id` 可省略（默认供应商 / 唯一已填 key）；认 `file://`；同视频（`platform:video_id`）复用上次转写缓存 |
| 生成 | `prepare_note_material` | 不调 LLM；同样认 `file://`；同样吃转写缓存 |
| 生成 | `batch_generate_notes` | 播放列表/分 P 服务端展开+逐个排队（`max_entries` 上限）；单条失败不阻断 |
| 解析 | `inspect_video` | 识别平台 + 检查链接 + 拆分 P / 播放列表（#136 并入 validate_url） |
| 任务 | `task` | action=status / transcript / cancel；未知 id → NOT_FOUND；轮询用 status，转写按需取；cancel 只发协作式事件，下一阶段边界生效，不能硬中断第三方阻塞调用；B 站弹幕/评论 helper 不接收该事件 |
| 任务 | `list_tasks` | 列出全部任务（全局索引，带语义标题） |
| 配置（只读） | `get_config` | `app_config` 默认值（过滤敏感项）+ `providers`（key 掩码）+ `transcriber` 就绪 + `cookie_configured`（平台名）；传 `provider_id` 附加连通性探测（用已存 key）。**修改一律走 CLI** |
| 系统 | `health_check` | 提交前体检：ffmpeg / 磁盘 / 转写器 / 供应商 key / 模型 / 任务队列；`url` 非空时顺带预解析时长；含 `server_version` |
| 媒体处理 | `process_media` | action=export（转写导出 srt/vtt/json）/ merge（多文件合并 16kHz mono wav）/ diarize（说话人分离；**拒绝** hf_token 参数）；同步执行，不登记任务注册表，不能用 `task(action="cancel")` 控制 |
| 清理 | `cleanup` | 传 `task_id` 按任务清理（含 `dry_run` 先查后清）；不传 = 全局清理（同步清空全局索引；config/models 默认保留；logs 不清） |

> 内部保留：`_stage_label`（`task` status 内部用，不再暴露为工具）；弹幕/评论/字幕抓取在 `generate_note` / `prepare_note_material` 内部完成（`include_comments` 参数）。

## 关键设计决策

1. **跨任务转写缓存**：同一视频（`platform:video_id`）再次生成，把上次转写从 `<数据目录>/note_cache/` 拷进 `gen/transcript.json` —— 下游 `has_transcript → skip_download` 自动跳过下载与转写。身份从 URL 预解析（B 站 BV+p / YouTube / 抖音 / TikTok / 小宇宙 eid / 小红书笔记 id；本地 sha256）；转写按来源分键（`subtitle` / `引擎[:尺寸]`），换引擎/尺寸不误用。全局 `cleanup` 一并清。
2. **无 RAG**：agent 读 Markdown / 转写，省去向量库。
3. **本地 + 云端转写并存**：默认 `fast-whisper`；可切 mlx / funasr / groq / bcut / kuaishou。
4. **后台线程 + 并发上限 3**：会话内可排队多个任务，但不要在同一条消息里并行塞多个 `generate_note`（客户端不稳）。
5. **密钥不进对话**：MCP 工具拒收 key/cookie/token；CLI 写 SQLite / config——落盘前经 Fernet（机器本地密钥 `fernet.key`，0600）加密，`providers`/`app_config` 读写自动加解密；MCP 响应恒掩码。
6. **generic 兜底**：未知 URL 先 yt-dlp，失败再让 Agent handoff。
7. **协作式取消**：任务持有 `threading.Event`，在字幕、下载、ASR、预处理、ffmpeg、抽帧、说话人分离、GPT chunk/后处理等边界检查并传播；可控的 ffmpeg/流式下载会终止或尽快退出，但无法硬中断第三方阻塞请求、模型推理或 SDK 调用。B 站弹幕/评论聚合 helper 仍不接收 `cancel_event`，因此该阶段取消要等 helper 返回。
8. **SQLite 迁移边界**：兼容迁移只对 SQLite 执行；`video_tasks` 缺表时 `_migrate_video_tasks` 是安全 no-op（新库仍由 `create_all` 建表）；迁移执行异常不再吞掉，而是记录并 re-raise，禁止以未知旧 schema 继续启动。
9. **持久化与并发边界**：普通任务 admission、submit、Future/Event 登记在同一 `_tasks_lock` 内，batch 明确旁路普通 admission 由线程池排队；DAO 的插入/更新/删除失败会 rollback 后 re-raise，流水线完成阶段的 `video_tasks` 索引失败因此阻止 SUCCESS。提交失败执行任务目录/manifest/索引回滚，清理失败以结构化诊断附加到原始异常，不替换原始错误。manifest 的 `RLock` 只覆盖同一进程，跨进程检查—删除 TOCTOU 仍为 P2。
10. **时长探测分层**：VideoReader 使用严格、带 120 秒超时的 ffprobe，非法时长直接失败；音频预处理的 `probe_duration` 是 best-effort，失败返回 0，由 `chunk_duration_guess` 回退 1800 秒并记录 warning。
